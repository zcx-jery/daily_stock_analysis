## 3. 产品背景

当前系统具备单股分析、历史回测、组合跟踪等能力，但缺少一个面向“全市场候选池”的短线筛选产品。

用户当前的真实需求不是：

- 只看某一只股票的基本面或 AI 分析

而是：

- 从今日强势股中，筛出明日更可能继续上涨的股票
- 在候选中进一步判断谁的弹性更强、风险更低
- 最终形成可执行的明日观察池和优先级列表

因此需要一个独立的产品能力，用于承接“全市场筛选 -> 多维评分 -> 明日 TopX 输出”的流程。

## 4. 产品定位

该产品不是“单股分析页”的补充功能，而是独立的全市场筛选器。

建议定位：

- 单股分析：回答“这只股票怎么看”
- 次日强势股筛选：回答“明天优先看哪几只”
- 回测：回答“这套筛选逻辑过去是否有效”

## 5. 目标用户

### 5.1 核心用户

- A 股短线交易者
- 偏打板、接力、强势股交易风格用户
- 每日收盘后做次日备选池的用户

### 5.2 次级用户

- 需要盘后复盘的交易者
- 想快速看市场强势方向的用户
- 想把强势股逻辑沉淀为标准化规则的研究者

## 6. 范围分层

### 6.1 当前 beta 已实现范围

当前上线页对应的是“收盘后次日筛选”的首个可用版本，重点解决：

- 手动执行一次强势股筛选
- 查看 `standard` / `aggressive` 两套画像结果
- 查看排序、亮点、风险与维度拆解
- 导出和复制当前结果

### 6.2 后续规划范围

以下能力不属于当前 beta 验收范围，而是后续规划：

- `V1.5`：收盘后增强版，补齐打板 / 接力 / 题材 / 筹码相关能力
- `V2`：盘中增强版，补齐分时强弱、回封质量、尾盘承接和动态排名

## 7. 当前 beta 已实现范围

### 7.1 当前版本目标

当前 beta 的目标是提供一个可用、可解释、可导出的“收盘后次日强势股筛选器”，帮助用户在收盘后快速得到：

- 今日涨幅超过阈值的候选池
- 明日延续概率较高的股票
- 明日弹性更强的股票
- 风险较高、需要回避的股票

### 7.2 当前页面与入口

- 页面名称：`强势筛选`
- 路由：`/screener`
- 导航入口：左侧边栏“强势筛选”
- 页面交互方式：用户手动点击“执行筛选”后才发起计算

### 7.3 当前支持的筛选参数

当前页面和 API 已支持以下输入：

| 参数 | 类型 | 是否当前可配 | 说明 |
|---|---|---|---|
| `profile` | enum | 是 | `standard` / `aggressive` 两套评分画像 |
| `top_n` | number | 是 | 返回前几只股票 |
| `min_change_pct` | number | 是 | 今日涨幅阈值 |
| `min_amount` | number | 是 | 最低成交额 |
| `min_turnover` | number | 是 | 最低换手率 |
| `trade_date` | date | 是 | 留空时优先尝试当天交易日；若当天收盘批量数据未同步完成，则自动回退到上一交易日 |
| `exclude_st` | boolean | 否，当前固定 | 当前 beta 固定为 `true` |
| `main_board_only` | boolean | 否，当前固定 | 当前 beta 固定为 `true` |

当前页面会自动记住：

- 上次使用的参数
- 当前排序方式

当本地没有缓存时，页面会从系统配置加载默认参数。

### 7.4 当前固定约束

当前 beta 为了控制复杂度，保留以下固定约束：

- 默认且固定排除 `ST/*ST`
- 默认且固定只看主板
- 不支持用户切换市场范围
- 不支持风险过滤开关
- 不支持板块筛选开关
- 不支持自定义评分权重
- 不支持盘中动态刷新

### 7.5 当前用户场景

#### 场景 1：收盘后生成明日观察池

用户在收盘后进入筛选页面，设置：

- 今日涨幅阈值 `N`
- 候选数量 `Top X`
- 最低成交额 / 换手率
- 评分画像

系统输出：

- 候选池数量
- TopN 排名结果
- 每只股票的主要加分与风险标签
- 维度拆解与个股详情

这是当前 beta 的核心场景。

#### 场景 2：盘后复盘涨停 / 强势股

该场景保留为后续增强方向，不属于当前 beta 核心验收。

#### 场景 3：盘中动态观察强弱变化

该场景属于 `V2` 规划，不属于当前 beta。

### 7.6 当前评分与排序

当前版本保留“多分数解释”设计，不只给一个总分。

#### `standard` 当前对外展示

- `continuation_score`：次日延续概率分
- `extension_score`：上涨弹性分
- `risk_score`：风险分
- `final_score`：基础总分扣除风险后的最终分
- `rank_score`：用于排序的排序分
- `entry_range_low` / `entry_range_high`：为二次决策与执行辅助派生的建议区间

当前 `standard` 排序公式为：

```text
rank_score = continuation_score * 0.65 + extension_score * 0.25 - risk_score * 0.10
```

#### `aggressive` 当前对外展示

在 `standard` 的基础上，`aggressive` 额外提供：

- `buyability_score`：可买分
- `opportunity_tag`：机会标签

两个画像在进入二次决策与执行辅助链路后，都可以携带 `entry_range_low` / `entry_range_high` 作为建议区间；其中 `aggressive` 为原生输出，`standard` 为派生输出。

当前 `aggressive` 排序公式为：

```text
rank_score = continuation_score * 0.55 + buyability_score * 0.25 + extension_score * 0.20 - risk_score * 0.12
```

#### 当前已实现的解释性信息

- `themes`：当前以板块映射结果为主
- `leader_level`：龙头 / 前排 / 中位 / 后排
- `top_reasons`：主要加分原因
- `risk_tags`：主要风险标签
- `score_breakdown`：维度拆解

### 7.7 当前页面结构

当前页面实际由 4 个核心区域构成：

1. 筛选参数区
2. 摘要卡区
3. 结果表格区
4. 单股详情抽屉

#### 筛选参数区

当前提供：

- 评分画像
- 返回数量
- 最小涨幅
- 最小成交额
- 最小换手率
- 交易日
- 执行筛选
- 恢复系统默认
- 重置

#### 摘要卡区

当前展示：

- 候选池数量
- 结果数量
- 平均排序分
- 最高排序分

#### 结果表格区

当前默认表格字段为：

- 排名
- 股票代码 / 名称
- 今日涨幅
- `rank_score`
- `continuation_score`
- `extension_score`
- `risk_score`
- `buyability_score`
- 板块
- 地位
- 操作

当前支持的排序方式：

- 按排序分
- 按延续分
- 按弹性分
- 按低风险优先
- 按可买分

#### 单股详情抽屉

点击结果行后，当前抽屉展示：

- 最终总分
- 排序分
- 延续分
- 风险分
- `aggressive` 下的可买分、机会标签、建议区间
- 板块、地位、亮点、风险标签
- 维度拆解

当前抽屉由用户点击结果行打开，并可通过关闭操作退出。

### 7.8 当前导出与复制能力

当前 beta 已支持：

- 复制当前结果集
- 导出 Markdown
- 导出 CSV
- 复制单股明细
- 导出单股 Markdown

- JSON 导出

## 9. V1.5 规划范围

### 9.1 版本定位

`V1.5` 定位为“收盘后增强版”，重点不是变成盘中系统，而是在收盘后版本里补齐更适合打板 / 接力 / 题材复盘的能力。

### 9.2 规划目标

在保留当前 beta 主流程的基础上，优先增强：

- 封板质量
- 炸板次数
- 连板状态
- 题材标签
- 筹码结构
- 更强的板块共振解释

### 9.3 规划数据依赖

按产品方案，`V1.5` 重点引入或增强：

- `limit_list_d`
- `kpl_list`
- `cyq_perf`
- `cyq_chips`

### 9.4 规划页面增强

`V1.5` 可以考虑逐步补齐以下非 beta 能力：

- 更丰富的市场概况区
- 候选池概览区
- 题材与梯队展示
- 更清晰的加分项 / 风险项分区
- 更完整的复盘导出内容

### 9.5 规划验收重点

`V1.5` 验收应重点关注：

- 打板 / 接力场景是否更有解释力
- 强势股与情绪冲高股是否区分更清楚
- 板块、题材、筹码相关指标是否稳定

### 9.6 真实性优先执行模式规划

随着 `V1.5` 正式接入题材成分、板块资金、个股承接和筹码风险等真值链路，强势筛选不再适合继续维持“用户点击一次按钮，然后同步等待完整结果返回”的执行方式。

`V1.5` 规划口径调整为：

- 用户点击“执行筛选”后，优先创建或复用一条 `screening run`
- 页面立即展示任务阶段、进度百分比、最近刷新时间和缓存命中提示
- 任务完成后自动加载最终筛选结果，而不是要求用户重新触发一次查询
- 用户离开页面后再次进入，仍可从“最近任务”继续查看正在执行或已完成结果
- 同参数、同版本、同口径的重复查询，应优先复用可验证的阶段缓存或最终结果

该规划的验收重点不是缩短同步 HTTP 耗时，而是确保：

1. 真值模式下不再为了网关超时长期裁剪 V1.5 数据能力。
2. 用户始终知道系统当前在做什么、做到哪一层、有没有复用缓存。
3. 同日重复查询的实际等待时间随缓存积累明显下降。
4. 失败、取消和降级状态有清晰边界，不把中间态误当成最终结论。

## 10. V2 规划范围

### 10.1 版本定位

`V2` 定位为“盘中增强版”，目标是在 `V1.5` 基础上补齐盘中动态判断。

### 10.2 规划目标

重点能力包括：

- 盘中分时强弱变化
- 封板过程分析
- 回封质量分析
- 尾盘承接变化
- 盘中动态排名

### 10.3 规划数据依赖

按产品方案，`V2` 需要引入实时分钟级数据，例如：

- `rt_min`
- 实时日线 / 分时数据能力

### 10.4 规划页面增强

`V2` 可能需要补充：

- 盘中动态刷新机制
- 分时维度可视化
- 回封 / 开板过程说明
- 午后强弱变化提示

### 10.5 规划验收重点

`V2` 验收应重点关注：

- 盘中数据延迟与稳定性
- 动态排名是否可靠
- 分歧转一致、回封质量等盘中判断是否具备可解释性

## 11. 后续增强项

以下属于后续可评估增强项，但当前未承诺进入具体版本：

## 12. 成功标准

### 12.1 当前 beta 成功标准

- 用户可以在 1 分钟内完成一次筛选
- 用户能快速理解前 `Top X` 的选择逻辑
- 每只股票的评分具有清晰解释
- 用户可以完成一次复制或导出

### 12.2 后续版本成功标准

- `V1.5` 能明显提升打板 / 接力 / 题材复盘场景的可用性
- `V2` 能在盘中提供稳定、可解释的动态强弱判断
