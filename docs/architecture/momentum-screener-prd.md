## 2. 产品背景

当前系统具备单股分析、历史回测、组合跟踪等能力，但缺少一个面向“全市场候选池”的短线筛选产品。

用户当前的真实需求不是：

- 只看某一只股票的基本面或 AI 分析

而是：

- 从今日强势股中，筛出明日更可能继续上涨的股票
- 在候选中进一步判断谁的弹性更强、风险更低
- 最终形成可执行的明日观察池和优先级列表

因此需要新增一个独立的产品能力，用于承接“全市场筛选 -> 多维评分 -> 明日 TopX 输出”的流程。

## 3. 产品目标

### 3.1 业务目标

构建一个可持续迭代的强势股筛选产品，帮助用户在收盘后或盘中快速得到：

- 今日涨幅超过阈值 `N` 的候选池
- 明日继续上涨概率较高的股票
- 明日上涨弹性更强的股票
- 风险较高、需要回避的股票

### 3.2 产品目标

提供一个独立页面和接口，支持用户完成以下动作：

1. 设置筛选条件
2. 生成候选池
3. 查看多维评分与排序结果
4. 查看每只股票的加分原因与风险原因
5. 导出或保存明日观察池

### 3.3 非目标

当前阶段不包含以下内容：

- 自动下单
- 实盘交易执行
- 完全黑盒的机器学习预测
- 基于分笔/逐笔的高频交易功能
- 多市场统一评分体系

## 4. 目标用户

### 4.1 核心用户

- A 股短线交易者
- 偏打板、接力、强势股交易风格用户
- 每日收盘后做次日备选池的用户

### 4.2 次级用户

- 需要盘后复盘的交易者
- 想快速看市场强势方向的用户
- 想把强势股逻辑沉淀为标准化规则的研究者

## 5. 用户场景

### 场景 1：收盘后生成明日观察池

用户在收盘后进入筛选页面，设置：

- 今日涨幅阈值 `N`
- 候选数量 `Top X`
- 是否只看主板
- 最低成交额 / 换手率

系统输出：

- 候选池总量
- 多维评分排序结果
- 明日重点观察股票列表
- 每只股票的主要加分与风险

### 场景 2：盘后复盘涨停/强势股

用户希望知道今天最强的一批股票里：

- 哪些是真强
- 哪些只是情绪冲高
- 哪些明日容易兑现

系统输出：

- 封板质量
- 炸板次数
- 板块共振
- 资金承接
- 风险标签

该场景主要对应 `V1.5`。

### 场景 3：盘中动态观察强弱变化

用户在盘中想实时看到：

- 强势股是否回封
- 尾盘承接是否增强
- 哪些股票从分歧转一致

系统输出：

- 分时强弱变化
- 回封质量
- 尾盘承接变化
- 盘中动态排名

该场景主要对应 `V2`。

## 6. 产品定位

该产品不是“单股分析页”的补充功能，而是独立的全市场筛选器。

建议定位：

- 单股分析：回答“这只股票怎么看”
- 次日强势股筛选：回答“明天优先看哪几只”
- 回测：回答“这套筛选逻辑过去是否有效”

## 7. 版本范围

### 7.1 V1：2000 分版

功能范围：

- 今日涨幅阈值筛选
- 收盘后多维评分
- 输出明日 TopX

适合：

- 收盘后观察池生成
- 首版产品上线

### 7.2 V1.5：5000 分版

功能范围：

- 继承 V1
- 加入封板质量、炸板次数、连板状态、题材标签、筹码结构

适合：

- 打板 / 接力评分
- 涨停与准涨停强势股复盘

### 7.3 V2：5000 分 + 实时分钟

功能范围：

- 继承 V1.5
- 加入盘中分时强弱、封板过程、回封质量、尾盘承接

适合：

- 盘中观察池动态更新
- 午后实时优选

## 8. 核心功能列表

### 8.1 条件筛选

用户可设置的筛选条件建议包括：

- 今日涨幅阈值
- `Top X`
- 市场范围
  - 主板
  - 创业板
  - 科创板
- 是否排除 ST
- 最低成交额
- 最低换手率
- 是否启用板块筛选
- 是否启用风险过滤

### 8.2 候选池生成

系统根据筛选条件生成候选池，并展示：

- 候选池数量
- 板块分布
- 主板/创业板分布
- 涨停股数量
- 非涨停强势股数量

### 8.3 多维评分

系统对每只股票执行多维评分。

当前基础评分维度：

- 强势确认质量
- 量价结构
- 趋势位置与形态
- 板块题材共振
- 资金承接质量
- 弹性与股性
- 风险修正

### 8.4 排名与结果展示

系统输出：

- 最终排序
- `continuation_score`
- `extension_score`
- `risk_score`
- `final_score`

### 8.5 单股详情展开

点击某只股票后，展示：

- 评分拆解
- 加分项
- 风险项
- 所属板块/题材
- 近几日走势摘要
- 是否属于龙头/前排/后排

### 8.6 结果导出与保存

建议支持：

- 导出 CSV / JSON
- 保存本次筛选快照
- 供后续回测或复盘使用

## 9. 页面结构

建议页面名称：

- 中文：`强势筛选`
- 英文：`Momentum Screener`

建议路由：

- `/screener`

### 9.1 页面结构总览

页面建议拆分为 5 个区域：

1. 条件筛选区
2. 市场概况区
3. 候选池概览区
4. 排名结果区
5. 单股详情侧栏或抽屉

### 9.2 条件筛选区

建议组件：

- 涨幅阈值输入框
- `Top X` 输入框
- 市场范围选择器
- 最低成交额输入框
- 最低换手率输入框
- 风险过滤开关
- 生成按钮

### 9.3 市场概况区

建议展示：

- 今日候选总数
- 今日涨停数
- 主板候选数
- 创业板候选数
- 最强板块
- 当前市场情绪标签

### 9.4 候选池概览区

建议展示：

- 板块分布图
- 候选池涨幅分布
- 候选池市值分布
- 涨停/非涨停比例

### 9.5 排名结果区

建议以表格为主，字段包括：

- 排名
- 股票代码
- 股票名称
- 今日涨幅
- `continuation_score`
- `extension_score`
- `risk_score`
- `final_score`
- 所属板块
- 龙头等级
- 风险标签

### 9.6 单股详情区

建议展示：

- 评分总览
- 各维度得分
- 主要加分原因
- 主要风险原因
- 趋势结构说明
- 板块地位说明
- 资金承接说明
- 历史股性说明

## 10. 输入与输出

## 10.1 输入

### 用户输入参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `min_change_pct` | number | 是 | 今日涨幅阈值 |
| `top_n` | number | 是 | 返回前几只 |
| `market_scope` | enum | 否 | 主板 / 创业板 / 科创板 / 全部 |
| `exclude_st` | boolean | 否 | 是否排除 ST |
| `min_amount` | number | 否 | 最低成交额 |
| `min_turnover` | number | 否 | 最低换手率 |
| `enable_risk_filter` | boolean | 否 | 是否启用风险过滤 |
| `trade_date` | date | 否 | 默认最近一个交易日 |

### 系统输入数据

主要依赖：

- 行情数据
- 基础股票信息
- 涨跌停数据
- 资金流向
- 龙虎榜
- 涨停/炸板专题数据
- 筹码结构数据
- 实时分钟数据

## 10.2 输出

### 页面输出

页面输出至少包括：

- 筛选条件回显
- 候选池数量
- TopX 排名结果
- 评分拆解
- 风险标签

### 结果对象建议

每只股票建议输出以下字段：

| 字段 | 说明 |
|---|---|
| `ts_code` | 股票代码 |
| `name` | 股票名称 |
| `pct_chg` | 今日涨幅 |
| `continuation_score` | 次日延续概率分 |
| `extension_score` | 上涨弹性分 |
| `risk_score` | 风险分 |
| `final_score` | 最终排序分 |
| `rank` | 当前排名 |
| `themes` | 所属题材/板块 |
| `leader_level` | 龙头/前排/中位/后排 |
| `top_reasons` | 主要加分原因 |
| `risk_tags` | 主要风险标签 |
| `score_breakdown` | 各维度拆解 |

## 11. 核心交互流程

### 流程 1：生成明日观察池

1. 用户进入强势筛选页面
2. 设置筛选条件
3. 点击生成
4. 系统计算候选池
5. 系统执行评分与排序
6. 返回明日 TopX
7. 用户点击单股查看详情

### 流程 2：查看单股评分拆解

1. 用户在结果表中点击某只股票
2. 页面展开详情侧栏
3. 展示评分维度拆解
4. 展示主要加分和风险标签

### 流程 3：保存观察池

1. 用户对本次结果满意
2. 点击保存或导出
3. 系统保存筛选快照
4. 后续供回测与复盘使用

## 12. 关键产品规则

### 12.1 排名规则

产品不能只给一个总分。

建议同时提供：

- `continuation_score`
- `extension_score`
- `risk_score`
- `final_score`

### 12.2 解释性要求

每只股票都必须可解释，不能只给黑盒分数。

至少应展示：

- 主要加分原因
- 主要风险原因
- 板块位置
- 资金质量

### 12.3 风险独立展示

风险项不能全部揉进总分。

页面应单独展示：

- 风险标签
- 风险分
- 主要扣分原因

## 13. 成功标准

产品上线后的成功标准建议包括：

- 用户可以在 1 分钟内完成一次筛选
- 用户能快速理解前 `Top X` 的选择逻辑
- 每只股票的评分具有清晰解释
- 后续回测可以验证筛选逻辑的稳定性
