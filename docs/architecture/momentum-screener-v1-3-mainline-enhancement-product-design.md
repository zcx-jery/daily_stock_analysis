## 2. 背景与结论

用户决定将 Tushare Pro 积分升级到 `6000`，但不购买股票实时分钟、股票历史分钟等独立分钟权限。

因此 V1.3 的产品定位不是“分钟级盘中买点系统”，而是：

**用 6000 积分可获得的题材、涨停、炸板、涨跌停价和热榜数据，把强势筛选从单股排序升级成主线驱动的短线决策系统。**

V1.3 的核心收益是：

- 候选池不再只回答“哪只股票强”，而是回答“它是不是在真正主线里强”。
- 二次决策不再只靠单股分数收口，而是结合主线强度、短线情绪和题材地位。
- 总闸门不再过度依赖 `20日 / 60日` 历史窗口，而是加入更贴近短线真实环境的主线和情绪证据。
- 回测不再只看赚没赚钱，而是能诊断错在主线、情绪、角色、价格位置还是候选池。

## 3. 数据权限边界

### 3.1 V1.3 可用数据

| 能力 | 接口 | 权限口径 | 用途 |
| --- | --- | --- | --- |
| 实时快照 | `realtime_quote` | 0 积分开放 | 当前价、开盘价、最高价、最低价、买卖盘快照 |
| 涨跌停价 | `stk_limit` | `2000` 积分起 | 涨停距离、跌停风险、追高红线、剩余空间 |
| 涨停 / 跌停 / 炸板 | `limit_list_d` | `5000` 积分起 | 短线情绪、连板高度、炸板风险、首封时间、封单强度、开板次数和封板质量 |
| 东方财富题材强度 | `dc_concept` | `5000` / `6000` 积分可用，按 Tushare 实际权限为准 | 题材强度、热度、涨停数、主力净流入、领涨股，用作真实资金主线主源 |
| 东方财富板块资金流 | `moneyflow_ind_dc` | `6000` 积分 | 行业 / 概念 / 地域板块主力净流入、超大单 / 大单净流入、排名 |
| 东方财富板块成分与行情 | `dc_member` / `dc_index` / `dc_daily` | `5000` / `6000` 积分可用，按 Tushare 实际权限为准 | 股票到东财板块映射、板块涨跌、上涨 / 下跌家数、领涨股、历史回放 |
| 开盘啦涨停题材 | `kpl_list` / `kpl_concept` | `5000` 积分，通常次日 08:30 左右更新 | 涨停原因、题材标签、打板语义、封单 / 换手 / 成交额 |
| 个股资金流 | `moneyflow_dc` / `moneyflow_ths` | `5000` / `6000` 积分可用，按 Tushare 实际权限为准 | 个股主力承接、超大单 / 大单流向，辅助主线内角色排序 |
| 筹码分布 | `cyq_perf` / `cyq_chips` | `5000` 积分 | 获利盘、成本分位、筹码压力，辅助追高风险 |
| 同花顺概念成分 | `ths_member` | `6000` 积分 | 股票到题材 / 概念 / 主线的映射 |
| 同花顺热榜 | `ths_hot` | `6000` 积分 | 热门股、热门概念和盘中关注度辅助判断 |
| 日线 / 每日指标 | `daily` / `daily_basic` | 常规积分接口 | 候选池、成交额、换手率、涨幅、历史验证 |

第一阶段优先接入 `dc_concept + moneyflow_ind_dc + dc_member / dc_index / dc_daily + kpl_list`，先解决“资金到底去了哪些强势板块”的根因识别问题。`moneyflow_dc / moneyflow_ths` 与 `cyq_perf / cyq_chips` 作为第二阶段增强，用于个股承接和追高风险细化。

### 3.2 V1.3 明确不可用数据

以下能力不在 6000 积分范围内，V1.3 不依赖这些能力：

- 股票实时分钟线。
- 股票历史分钟线。
- 分时均线 / VWAP。
- 逐笔成交。
- Level-2 十档盘口。
- 自动交易或券商下单接口。

### 3.3 产品表达边界

V1.3 盘中区域必须称为 `盘中快照辅助`，不得称为“正式分钟级买点”。

允许输出：

- `价格接近观察区`
- `强度条件满足`
- `主线仍有支撑`
- `偏离过大，不建议追`
- `快照低置信度触发`
- `数据不足，等待人工确认分时承接`

不允许输出：

- `分时承接已确认`
- `VWAP 承接成立`
- `分钟级买点正式触发`
- `建议买入`

补充边界：

- `limit_list_d` 可用于解释 T 日封板质量，例如早封强封、尾盘弱封、多次开板和一字难参与。
- 封板质量只能辅助 `买点清晰度 / 风险解释 / 落选原因`，不能被包装成分钟级封板确认。
- 一字板或极端缩量板只能说明强度确认，不代表次日好买；页面应明确提示 `强封但难参与`。
- `limit_list_d` 缺失或关键字段不完整时，只能降低置信度，不得硬扣分或硬阻断。

## 4. V1.3 产品目标

V1.3 的目标是完成四个升级：

1. **主线识别升级**：从行业文本和单股排序，升级为题材成分映射与主线强度评分。
2. **短线情绪升级**：接入涨停、炸板、连板、热榜等数据，判断当天是否适合做强势股。
3. **组合收口升级**：主仓 / 次仓 / 观察仓结合题材内地位、角色分工和情绪环境。
4. **回测诊断升级**：把失败原因拆成主线弱、情绪差、角色错、价格过热、候选池偏差等可行动问题。

一句话：

**V1.3 不是让系统更会“喊买点”，而是让系统更会判断今天哪条主线、哪几只核心票值得认真看。**

## 5. 主链路设计

V1.3 的官方链路调整为：

```text
全市场统一入口
-> 候选池
-> 题材 / 概念映射
-> 完整排序集
-> 主线强弱评分
-> 短线情绪总闸门
-> 候选股角色识别
-> Standard 官方 Top3
-> 淘汰原因
-> 盘中快照辅助
-> 回测诊断
-> AI 解释
```

关键变化：

- `Standard` 仍然是唯一官方主链路。
- `Aggressive` 仍然只是进攻补充观察层。
- 官方 Top3 不再只从单股分数收口，而是从 `强势股 + 所属主线 + 情绪环境 + 角色地位` 联合收口。

### 5.1 执行模式升级：真实性优先的任务化筛选

当 V1.3 真值链路开始正式接入逐股题材成分、板块资金、个股承接和筹码风险后，强势筛选不再适合继续被建模为“同步 HTTP 请求必须在网关超时内完成”的页面动作。

产品口径调整为：

- 用户点击“执行筛选”后，系统优先创建或复用一条 `screening run`。
- 页面立即进入“任务进行中”状态，展示当前阶段、进度百分比、最近刷新时间和已命中的缓存层。
- 任务完成后自动加载最终结果；如果存在完全同参、同版本、同口径缓存，可直接返回已完成 run。
- 用户离开页面后再次进入，仍可从“最近任务”或 `run_id` 继续查看。
- 任务失败、取消或降级时，页面必须明确告诉用户卡在哪一层，而不是只返回通用报错。

这次升级的产品原则是：

1. 真实性优先于同步返回速度。
2. 进度反馈优先于空白等待。
3. 结果复用优先于重复全量重算。
4. 未完成任务、已完成结果和降级结果必须有清晰边界，避免用户把中间态误认为最终结论。

### 5.1.1 无损快照优先的执行原则

真实性优先不等于接受低效串行调用。产品层需要明确区分：

- **可无损快照的数据**：允许按交易日全量、按全表分页或按批量参数一次性拉回，再在本地完成过滤、映射和归因。
- **必须逐股真查的数据**：保留完整维度，但通过任务化、缓存和预热降低重复请求。

经 `2026-04-27` Tushare 文档与测试服实测，当前 V1.3 / V1.5 题材链可按以下原则设计：

| 类型 | 接口 | 产品侧结论 |
| --- | --- | --- |
| 可按交易日全量快照 | `moneyflow_ths` / `moneyflow_dc` / `dc_index` / `moneyflow_ind_dc` | 默认按日快照拉取，不再逐股或逐题材散点查询 |
| 可分页快照 | `cyq_perf` / `dc_member` / `ths_member` / `ths_index` | 先分页拉完整快照，再做股票到题材、资金、筹码的本地映射 |
| 必须逐股真查 | `cyq_chips` | 不削弱维度；通过任务化 run、持久缓存、预热和断点续跑控制耗时 |

用户体验上的含义是：

1. 任务耗时长时，页面应告诉用户“正在构建完整真值快照”。
2. 真值任务的提速来源应优先是“更多命中快照缓存”，而不是“少查一些维度”。
3. 若某个维度暂时不可快照，系统只能展示为“仍在补齐”或“该维度缺失”，不能静默改成低配评分。

### 5.1.2 排序引擎重构需求冻结（2026-04-27）

本轮 `6000` 积分升级的核心目标，明确冻结为：

**重构 V1 旧版主排序逻辑，而不是继续把 V1.3 停留在影子分、局部增强或二次决策补充层。**

产品侧要求如下：

1. `初筛` 只负责候选入口过滤，不再承担最终强弱排序结论。
2. `初筛后全部候选股票` 都必须进入新一代重评分链路，而不是只增强 `Top12`、`Top30` 或页面展示子集。
3. 官方 `Standard` 排序分应直接吸收 `6000` 积分可获得的新数据维度，包括但不限于：
   - 真实题材成分映射
   - 板块资金强度与共振
   - 个股资金承接
   - 涨停 / 炸板 / 开板结构
   - `kpl_list` 状态与换手语义
   - `cyq_perf / cyq_chips` 提供的筹码压力
4. `Aggressive` 仍然是补充观察层，但其进攻排序也应建立在同一套全候选新画像上，而不是旧分数旁路。
5. `影子分`、`V1.3 题材雷达`、`二次决策解释` 可以保留，但它们不再视为本次升级的主交付物，只能作为诊断与解释层。

明确禁止把以下做法当作最终方案：

- 旧 `V1` 排序公式保持主体不变，只对前几只股票做 V1.3 加权修饰。
- 用 `Top12` 或 `Top30` 局部增强替代“初筛后全候选重评分”。
- 因为性能压力而删减主评分维度，导致排序真实性下降。

后续如果要做性能优化，只允许通过：

- 快照化批量取数
- 任务化执行
- 缓存复用
- 断点续跑

来支撑全候选重评分，不允许通过减少评分覆盖范围来换速度。

### 5.1.3 用户侧排序口径冻结（2026-04-27）

用户侧个股列表的排序心智，统一冻结为：

1. 个股列表只保留一个正式排序结果。
2. 该正式排序结果对外统一命名为：`官方总分`。
3. `????` ????????? `official_score`?????????????????????????????????????
4. `final_score`、`continuation_score`、`extension_score`、`risk_score`、`buyability_score` 保留，但只作为解释维度，不再作为普通用户可切换的列表排序方式。
5. `影子分`、`题材雷达`、`二次决策解释` 也只承担解释职责，不单独成为用户侧新的平行排序口径。

因此，页面应避免继续向普通用户暴露以下心智：

- 按延续分重新洗牌官方结果
- 按弹性分重新洗牌官方结果
- 按低风险优先重新洗牌官方结果
- 按可买分重新洗牌官方结果

系统需要给出一个正式顺序，其他分值只负责解释这个顺序，而不是邀请用户在多个分值里自行挑选“更相信哪一个”。

### 5.1.4 `官方总分` 的正式产出链（2026-04-27 冻结）

为避免“旧排序结果 + 局部增强 + 二次决策补丁”继续混杂，`官方总分` 的产品产出链冻结为：

```text
候选池初筛
-> 初筛后全候选股票
-> 全候选构建 V1.3 / V1.5 新画像
-> 全候选统一重评分
-> 产出唯一正式顺序（官方总分）
-> 页面 Top30 展示
-> 二次决策读取完整正式顺序做组合收口
```

对应的产品含义是：

1. 页面展示的 Top30，不再是“旧排序结果里最前面的 30 只，再额外给前几只补点新信号”，而是**全候选统一重评分后的前 30 只**。
2. `官方总分` 的排序对象是**初筛后的全部候选股**，不是页面当前可见股票，不是 Top12，也不是某个解释层子集。
3. 二次决策从这里开始只做“怎么用这份正式顺序”，不再负责修正“这份正式顺序对不对”。
4. 详情页、AI 点评、导出明细展示的各项分值，必须服务于解释 `官方总分` 为什么排成这样。

因此，用户侧应稳定形成这样的心智：

- `官方总分` 回答：谁更强
- `二次决策` 回答：今天怎么做
- `解释层分值` 回答：为什么这样排、为什么这样收口

## 6. 主线识别

### 6.1 股票到题材映射

系统基于 `ThemeStrengthProvider` 建立以下关系：

```text
真实板块强度 -> 股票 / 板块映射 -> 父题材归并 -> 候选池覆盖 -> 当日主线候选
```

主数据优先级为：

1. `dc_concept` / `moneyflow_ind_dc`：优先判断当天真实强板块和资金流向。
2. `dc_member` / `dc_index` / `dc_daily`：建立股票到东财板块的映射，并补充板块涨跌、宽度和领涨信息。
3. `kpl_list`：补充涨停原因和打板题材语义，尤其用于解释涨停股为什么被市场选择。
4. `ths_member` / `ths_hot`：作为同花顺口径的题材成分和热度补充。
5. 父题材词库：在多个碎片概念同时指向同一产业链时，归并为用户可复盘的大题材。

同一股票可以属于多个题材。第一版不强行唯一归因，而是保留多题材映射，并在二次决策中按以下顺序选择主归因：

1. 当日该题材在真实板块强度或资金净流入中排名更靠前。
2. 该题材覆盖候选池强势股更多，且能解释 Top10 / Top30 的集中爆发。
3. 该题材内涨停、连板、炸板表现更强。
4. 该题材热榜或资金关注度更高。
5. 股票自身在该题材内排序更靠前。

### 6.1.1 真实板块强度归因口径

V1.3 主线识别首先回答“今天市场资金去了哪里”，而不是优先展示原始概念代码。

真实主线成立时，页面必须展示：

- 父题材名称，例如 `电池`。
- 来源子题材，例如 `锂电池概念 / 电池技术 / 锂矿概念 / 固态电池`。
- 板块排名、强度分、主力净额、涨停数、上涨 / 下跌家数。
- 覆盖的候选股和代表股。
- 数据来源、数据时间和降级状态。

示例口径：

```text
电池
-> 来源子题材：锂电池概念、电池技术、锂矿概念、固态电池
-> 资金证据：概念净流入靠前，行业“电池”净流入靠前
-> 候选覆盖：多氟多、天华新能、恩捷股份、天赐材料、盛新锂能、天齐锂业
```

如果只能拿到 `886089.TI`、`700457.TI` 这类原始代码而无法翻译成题材名称，页面不得把它作为主结论直接展示，只能放入调试或数据来源明细。

### 6.2 主线评分

主线评分由五个维度组成：

| 维度 | 说明 |
| --- | --- |
| 主线密度 | 候选池内同一题材股票数量、Top30 占比、Top10 占比 |
| 涨停强度 | 题材内涨停数、连板数、封单质量、涨停统计 |
| 炸板风险 | 题材内炸板数量、炸板率、开板次数 |
| 资金热度 | `dc_concept` 强度 / 热度 / 主力净额、`moneyflow_ind_dc` 净流入和排名、`dc_index` 上涨 / 下跌家数、热榜热度 |
| 延续反馈 | 昨日候选池 Top10、昨日官方 Top3 的次日表现 |

第一版主线结论分四档：

- `主线极强`
- `主线成立`
- `主线存疑`
- `非主线 / 主线过弱`

### 6.3 主线展示

页面新增 `主线雷达` 区域：

- 展示当日最强 `1-2` 条主线。
- 每条主线展示：`主线名称 / 强度分 / 主力净额 / 板块排名 / 涨停数 / 炸板风险 / 候选池占比 / 覆盖子题材 / 数据源状态 / 代表股`。
- 若系统无法稳定识别主线，必须显示 `主线不清晰`，不能强行归因。

## 7. 短线情绪总闸门

V1.3 的总闸门新增 `短线情绪` 模块。

短线情绪回答的问题是：

**今天市场是否愿意继续奖励强势股和主线核心票。**

### 7.1 情绪输入

| 输入 | 说明 |
| --- | --- |
| 涨停数量 | 全市场涨停数量与主线内涨停数量 |
| 炸板率 | 全市场炸板率与主线内炸板率 |
| 连板高度 | 最高连板、主线内连板梯队 |
| 昨日强势反馈 | 昨日候选池 Top10 + 昨日官方 Top3 次日表现 |
| 热榜集中度 | 热门股和热门题材是否集中在同一主线 |

### 7.2 情绪结论

短线情绪分四档：

- `高涨`
- `可做`
- `分歧`
- `退潮`

对总闸门影响：

- `高涨`：允许总闸门上调一档，但不得绕过买点和风险边界。
- `可做`：不额外加减分。
- `分歧`：限制强信任表达，优先输出谨慎或观察。
- `退潮`：除非主线和机会质量极强，否则最高只保留观察。

## 8. 角色与组合升级

### 8.1 龙头核心

V1.3 中 `龙头核心` 不再只靠 rank score 判断，必须结合：

- 所属主线强度。
- 题材内涨幅 / 成交额 / 涨停或连板地位。
- 是否能带动同题材其他股票。
- 是否在昨日或近期强势反馈中保持核心地位。

### 8.2 前排换手

`前排换手` 重点看：

- 主线内排序靠前。
- 成交额和换手率健康。
- 不是纯后排跟风。
- 涨停 / 炸板 / 回封结构没有明显硬伤。

### 8.3 观察备选

`观察备选` 不再只是第三名，而是：

- 主线确认票。
- 补涨潜力票。
- 或者主线风向标。

如果当天只有两只票具备明确价值，系统仍然只输出两只，不强凑第三只。

## 9. 盘中快照辅助

V1.3 继续保留盘中刷新，但产品定位必须降级为 `快照辅助`。

### 9.1 可判断内容

- 当前价是否接近观察区。
- 当前价是否偏离过大。
- 当前价距离涨停价还有多少空间。
- 当前主线是否仍有涨停 / 热榜 / 强势股支撑。
- 官方 Top3 中谁仍值得继续观察。

### 9.2 不可判断内容

- 分时均线承接。
- VWAP 回踩修复。
- 分钟级量价背离。
- 真实盘中回封质量。
- 严格分钟级买点触发。
- 仅凭一字板或日线封板强度得出“次日可买”的结论。

### 9.3 页面表达

盘中卡片统一显示：

- `当前状态`
- `置信度`
- `快照依据`
- `还差哪些人工确认条件`

示例：

```text
当前状态：价格接近观察区，主线仍有支撑。
置信度：中低。
快照依据：当前价距离观察区上沿 1.2%，所属主线仍有 3 只涨停。
还差条件：需要人工确认分时回踩承接，不可仅凭快照追入。
```

## 10. 回测诊断升级

V1.3 回测不只输出收益结果，还要输出失败归因。

### 10.1 新增诊断维度

| 诊断项 | 说明 |
| --- | --- |
| 候选池偏差 | 当日真正强势主线未进入候选池，或候选池过窄 |
| 主线识别错误 | 系统选错主线，或主线强度判断过高 |
| 角色识别错误 | 龙头 / 前排 / 观察仓分配不合理 |
| 情绪环境错误 | 退潮期仍输出过强动作，或强情绪期过度保守 |
| 价格位置错误 | 票选对了，但价格过热、追高空间不足 |
| 总闸门过紧 | 有明显机会但被历史窗口或风险项压死 |
| 总闸门过松 | 情绪或主线已弱，系统仍给出过强结论 |

### 10.2 核心比较基准

V1.3 回测至少比较：

- 官方 Top3 vs 全候选池基准。
- 官方 Top3 vs Raw Momentum Top3。
- 官方 Top3 vs 候选池 Top10。
- 主仓 vs 次仓 / 观察仓。
- 主线内入选票 vs 主线内未入选高分票。
- 劝退日 vs 如果强行买入的结果。

其中 `Raw Momentum Top3` 固定使用初筛候选在 T 日可见的 `rank_score` 降序选出，不经过 V1.3 二次决策、主线收口和画像过滤；`全候选池基准` 使用固定入口 `涨幅 >= 4% / 成交额 >= 2亿 / 换手率 >= 2%` 形成的完整候选池。

### 10.2.1 Benchmark Comparison Logic

Stage 2 起，V1.3 回测必须输出三组可交易合格率对比，用来证伪过滤层是否真正有价值：

- Group A（V1.3 Official）：经过 V1.3 主线、画像、二次决策和总闸门收口后的官方 Top3。
- Group B（Raw Momentum）：只按初始 `rank_score` 选出的 Top3，绕过 Secondary Decision 和 Mainline 检查。
- Group C（Market Base）：完整候选池平均表现，即固定入口 `涨幅 >= 4% / 成交额 >= 2亿 / 换手率 >= 2%` 的全池样本。

核心结论字段：

- `V1.3 Alpha vs Pool = Group A 可交易合格率 - Group C 可交易合格率`。
- `Selection Efficiency = Group A 可交易合格率 - Group B 可交易合格率`。
- 如果 `Group A < Group C`，报告必须标记 `LOGIC FAILURE: Screener is destroying Pool Alpha`，说明筛选器正在破坏候选池本身的 Alpha。
- 如果 `Group A < Group B`，说明 V1.3 过滤层可能过度主观，需复核主线、画像、封板强度和总闸门参数。

### 10.3 成功标准

60 个交易日回测中，V1.3 至少需要证明：

- 官方 Top3 的可交易合格率不得低于全候选池基准，否则视为过滤层逻辑失败。
- 官方 Top3 相对 Raw Momentum Top3 的 `Selection Efficiency` 不得长期为负，否则需要复核二次决策与画像过滤是否错杀强势龙头。
- 官方 Top3 相对候选池 Top10 至少不弱，或利润窗口更高且回撤不明显恶化。
- 主线强度高的日期，官方 Top3 表现明显优于主线不清晰日期。
- `退潮 / 分歧` 日的降级能减少亏损或减少无效出手。
- 主仓长期不弱于组合内其他角色。
- 失败样本能被归因到可解释类别，而不是只显示亏损。

## 11. AI 点评升级

V1.3 给 AI 的输入必须升级为结构化证据，而不是只给股票列表。

AI 点评可使用：

- 今日总闸门结论。
- 主线雷达。
- 短线情绪。
- 涨停 / 炸板 / 连板证据。
- 题材成分映射。
- 官方 Top3 角色理由。
- 落选主因。
- 回测诊断摘要。

AI 仍然不能替代规则层做最终决策，只负责：

- 解释。
- 补充风险。
- 追问回答。
- 帮用户理解系统为什么这么判断。

## 13. 风险与降级

- `realtime_quote` 是爬虫版实时快照，数据质量不稳定，必须支持失败降级。
- `dc_concept`、`moneyflow_ind_dc`、`dc_index` 更适合收盘后或接近收盘后的板块强度判断，盘中使用时必须展示 `data_as_of`，不能包装成分钟级实时资金信号。
- `kpl_list` 通常在次日更新，更适合复盘、回测和题材语义补充；若用于当日诊断，必须明确数据时间。
- AkShare / 东方财富 Web 口径容易受网页接口波动影响，只能作为 fallback，不能替代 Tushare 主源。
- 东方财富、同花顺、开盘啦之间可能存在板块命名差异，必须保留 `source_status`、`source_child_themes` 和父题材归并依据。
- 真实板块强度数据缺失时，系统可降级到 `ths_member + ths_hot + 父题材词库`，但必须降低置信度并显示降级原因。
- `ths_member` 是题材成分口径，股票多题材归属会带来主线归因冲突。
- `ths_hot` 更偏关注度，不等于真实资金强度，只能作为辅助证据。
- 没有分钟线时，盘中信号不能过度承诺。
- 涨停 / 炸板数据可能是盘后或延迟数据，盘中使用时必须标注数据时间。

## 14. V1.3 最短版

如果只记 V1.3，可以记住这 `8` 条：

1. V1.3 的核心不是分钟级买点，而是主线增强。
2. 6000 积分能支撑题材、涨停、炸板、热榜和涨跌停价，不支撑分钟线。
3. 系统从单股排序升级为 `强势股 + 主线 + 情绪 + 角色` 联合判断。
4. 页面新增主线雷达和短线情绪，但盘中区域必须降级为快照辅助。
5. `Standard` 仍是唯一官方链路，`Aggressive` 仍是补充观察层。
6. 总闸门新增主线和情绪证据，20/60 只做温度和信任折扣。
7. 回测必须能诊断错因，而不是只给收益结果。
8. AI 只解释结构化证据，不替代规则层决策。
