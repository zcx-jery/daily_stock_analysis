## 2. 文档目标

本 PRD 用于把原始 SPEC 拆解成完整、可协作的产品需求，供产品、设计、前端、后端、测试共同理解以下内容：

- 目标用户是谁
- 该功能解决什么问题
- 页面需要提供哪些核心能力
- 用户在 T 日收盘后与 T+1 盘中的操作路径是什么
- 页面状态、推荐逻辑、证据逻辑和降级逻辑如何配合
- 研发验收时应重点关注哪些产品行为

## 3. 背景与目标

### 3.1 当前背景

现有强势筛选页已经能完成以下基础能力：

- 从候选池中筛出强势股结果
- 支持 `Standard / Aggressive` 两套底层筛选逻辑
- 展示排序结果与个股详情
- 输出 TopN 候选池与明细指标

但从用户真实交易行为看，当前产品仍停留在“给出一堆结果”，还没有真正走到“帮助用户在明天做更少错误的决定”。

### 3.2 业务目标

本次新增的 `二次决策` 能力，不是为了替代现有筛选页，而是为了把“筛选结果”进一步收口成“明日可执行的候选顺序与信号辅助”，目标包括：

- 帮用户从候选股中明确谁更值得看、谁更值得等买点
- 帮用户建立对推荐顺序的信任，而不是只看到一堆分数
- 帮用户减少在买点未形成时提前追高的错误
- 帮用户在次日开盘后 60 分钟内更稳定地形成 `买 / 不买` 决定

## 4. 目标用户

### 4.1 核心用户

- A 股短线交易用户
- 会看盘、会看强势股与主线
- 还不会系统化选股与排序
- 每天收盘后会从候选池收敛到 2-5 只股票
- 次日有明确的短线执行需求

### 4.2 典型能力边界

这类用户通常：

- 能看懂哪些票强
- 能大致收敛到 3 只左右
- 但分不清哪只更值得买
- 也不清楚为什么自己该等、该放弃、该观察

### 4.3 典型错误行为

- 买点未触发时提前买入
- 看见主线强就直接追高
- 3 只候选里买了次优票
- 今天其实应观察或不做，却仍然硬做

## 5. 核心问题陈述

### 5.1 核心问题

用户当前最大的问题不是“没有候选票”，而是：

`已经能把候选池收敛到 3 只左右，但分不清谁更值得买、为什么更值得买、明天应该怎么等买点。`

### 5.2 当前产品的主要缺口

- 缺少推荐顺序与仓位角色解释
- 缺少为什么选它、不选它的透明解释
- 缺少明日是否适合出手的总判断
- 缺少主线、买点、证据三者之间的闭环
- 缺少盘中信号失真时的低置信度降级机制

## 6. 产品定位

本产品的定位不是传统选股器，也不是自动交易系统，而是：

`一个先排序、再给次日执行信号的两阶段助手。`

### 6.1 第一阶段：T 日收盘后二次决策

系统在现有强势筛选结果基础上，完成以下工作：

- 识别 `1-2 条主线`
- 为每条主线选择 `龙头核心 / 前排换手 / 观察备选`
- 生成默认 `主仓 / 次仓 / 观察仓`
- 给出今日出手级别与一句理由
- 解释为什么入选、为什么落选
- 提供证据区与历史相似案例

### 6.2 第二阶段：T+1 盘中信号辅助

系统不改变前一晚的排序，只在次日早盘观察是否形成可执行信号：

- 哪只票接近或进入买点
- 哪只票掉队
- 是否进入低置信度
- 到 60 分钟内是否形成 `建议买 / 不建议买`

## 7. 产品原则

- 系统给出明确排序与强烈倾向，但不替用户完成最终买卖执行
- 排序是系统正式判断结果，用户默认不能手改
- 页面必须能解释“为什么是这个顺序”
- 页面必须允许“今天不给满 3 只”
- 页面必须在关键不确定时诚实降级，而不是硬给结论

## 8. 范围界定

### 8.1 Phase 1 在做什么

- 基于现有强势筛选页新增 `二次决策`
- 支持主线识别、默认组合、证据区、行动清单、盘中信号
- 聚焦 `T 日筛股 -> T+1 买点辅助`

### 8.2 Phase 1 不做什么

- 不做自动交易
- 不做完整卖出系统
- 不开放大量参数
- 不覆盖港股、美股、中线策略
- 不把产品做成教学平台

## 9. 页面结构

`二次决策` 视图建议在现有强势筛选页内新增 Tab，不另起产品入口。

### 9.1 页面区块

页面从上到下分为：

1. 今日出手级别
2. 主线识别与默认组合
3. 推荐股卡片区
4. 候选池落选解释区
5. 证据区
6. 明日行动清单

### 9.2 今日出手级别

展示内容：

- 五档状态：`强烈可做 / 可正常出手 / 谨慎出手 / 仅观察 / 今日不做`
- 一句理由

判定逻辑：

- 由 `策略健康 + 主线清晰度 + 默认组合质量` 综合决定
- 采用强一票否决
- `策略停用` 直接落 `今日不做`
- `买点不清晰` 时：
  - 若 `主线极强`，最多 `仅观察`
  - 若主线不够强，直接 `今日不做`

### 9.3 主线识别区

目标：

- 明确告诉用户今天在看哪 1-2 条主线
- 让用户先理解“市场主攻方向”，再看个股

输出内容：

- 主线名称
- 主线综合强度
- 主线是否达到 `极强`
- 每条主线的代表股

### 9.4 默认组合区

展示系统正式排序结果：

- `主仓`
- `次仓`
- `观察仓`

组合原则：

- `主仓` = 明天买点最清晰的那只
- `次仓` = 进攻性更强但确定性略弱
- `观察仓` = 主线确认票
- 允许只输出 1-2 只，不强凑第三只

### 9.5 推荐股卡片

每张卡片优先回答：

`为什么它适合放在这个仓位`

卡片展示顺序：

1. 主线视角
2. 主线地位 + 明天买点 / 执行理由
3. 组合作用

### 9.6 落选解释区

所有未入选票都要给出 `一个主因`，用于提升透明度。

主因优先级：

- `非主线 / 主线过弱`
- `主线内名次不够`
- `角色重复`
- `买点不清晰`
- `近期验证弱`

### 9.7 证据区

证据区不和推荐卡片混在一起，避免上半屏信息过重。

优先顺序：

1. 这条主线最近值不值得做
2. 为什么今天系统敢给这个结论
3. 每只推荐股 1 个最像的历史案例
4. 组合验证 / 角色验证 / 主线验证等次级证据

### 9.8 明日行动清单

仅在 `强烈可做 / 可正常出手` 时展示。

清单按时间组织：

- 开盘前
- 开盘后 30 分钟
- 开盘后 60 分钟内

## 10. 关键规则说明

### 10.1 主线极强

采用 `先硬门槛、再看综合分` 方式判定。

前置硬门槛：

- 梯队完整
- 强势股密度高

补充条件：

- 资金支持强

#### 强势股密度高

- 同时看 `绝对数量` 与 `相对密度`
- 以 `相对密度` 为优先
- 核心是看该主线是否形成明显强势集中

#### 梯队完整

- 必须存在明确 `龙头核心`
- 若没有明确龙头核心，则不能判为完整
- 若有龙头但没有足够好的前排换手，则只能判 `偏强`，不能判 `极强`

#### 资金支持强

- 主判定为 `分歧中的承接、回封与回流`
- 辅助验证为 `持续赚钱效应与增量资金回流`
- 需满足链路：`分歧砸盘 -> 承接横住 -> 回流转强 / 修复回封`

### 10.2 买点清晰

`买点清晰` 的核心定义是：

`买入区间清楚且可执行`

成立条件：

- 至少存在一个 `最优买入区`
- `次优观察 / 补买区` 为增强项，不是硬门槛
- 区间必须锚定 `客观价格参考点`
- 区间不能过宽

当前角色阈值：

- `龙头核心`：最优买入区最大宽度 `<= 2%`
- `前排换手`：最优买入区最大宽度 `<= 3%`

#### 龙头核心买点

- 优先围绕 `次日盘中强承接位`
- 强承接位需满足：
  - 回落至均价线附近后有明显承接
  - 急杀后能横住形成平台
  - 随后重新转强

#### 前排换手买点

- 优先围绕 `分时均价线附近`
- 更强调：
  - 均价线附近充分换手后站稳
  - 或短暂跌破后快速拉回
  - 整体更偏向充分换手后再上攻

### 10.3 低置信度

`低置信度` 的第一触发原因不是数据缺失，而是：

`系统内部关键信号冲突`

优先触发场景：

- 昨晚排序强
- 次日早盘实际表现不支持

具体表现：

- 主仓迟迟不接近买点
- 主仓竞价 / 开盘 / 承接明显低于预期
- 次仓 / 观察仓强度明显反超主仓
- 总体上昨晚排序与次日实际走法明显背离

降级动作：

- 一旦进入 `低置信度`
- 系统不再输出明确 `建议买`
- 仅保留观察信息、原因说明、待验证条件

恢复条件：

- 只有当 `原排序重新被盘面验证`
- 才允许恢复明确买入信号

### 10.4 价格偏离过大

`价格偏离过大` 的本质不是“票变弱”，而是：

`票仍可能强，但当前位置已经不值得追`

最终判定依据：

- 潜在利润空间被压缩
- 潜在风险回撤被放大
- 导致综合盈亏比显著劣化

#### 龙头核心

若当前价格相对后续 `回踩分时均线或关键承接位` 的潜在跌幅，已超过 `次日预期溢价空间`，则视为偏离过大。

#### 前排换手

满足以下任一条件即视为偏离过大：

- 当前价格相对 `分时均线` 的偏离度 `> 3%`
- 当前到涨停位的剩余上涨空间，不足潜在回撤空间的 `1.5 倍`

处理方式：

- 不直接移出组合
- 保留在组合与主线结构中
- 明确标注 `不建议追入`
- 持续观察是否出现结构修复后的新买点

## 11. 盘中交互流程

### 11.1 T 日收盘后

系统完成：

- 主线识别
- 默认排序
- 入选 / 落选解释
- 证据区准备
- 明日行动清单生成

### 11.2 T+1 开盘前

页面重点输出：

- 三只推荐股谁的预期开盘状态更强
- 用户应该先盯谁

### 11.3 T+1 开盘后 30 分钟

页面重点输出：

- 谁掉队了
- 哪些票明显低于预期
- 哪些票仍值得继续观察

### 11.4 T+1 开盘后 60 分钟内

系统必须收口成：

- `建议买 / 不建议买`

如果建议买：

- 明确 `优先关注哪一只`
- 明确 `次选哪一只`
- 其余继续观察

如果不建议买：

- 保留观察信息
- 明确标注 `不建议执行买入`

## 12. 状态与边界

### 12.1 策略健康状态

- `20 日窗口`：判断当前还能不能用
- `60 日窗口`：判断结构是否仍可信

状态含义：

- `20 + 60` 同时健康：完整强推荐
- 仅一边健康：输出 `1-2` 只或仅观察
- 两边都失效：策略停用

### 12.2 停用状态

停用时页面仍保留：

- 候选池
- 筛选结果
- 观察区
- 恢复条件

但不再给：

- 强推荐组合
- 强买点
- 明确建议买

### 12.3 恢复状态

恢复采用 `先观察后恢复`：

- `20 日` 先恢复：恢复到观察 / 少量推荐
- `60 日` 也恢复：恢复完整强推荐

## 13. 验收重点

### 13.1 本阶段主验收

- 策略层有效
- 页面能完整闭环
- 规则能稳定产出主线、排序、信号、证据、降级状态

### 13.2 用户层观察指标

- 用户在开盘后 60 分钟内明确 `买 / 不买` 的天数上升
- 用户在 `未触发买点` 状态下提前买入的次数下降

### 13.3 明确说明

本阶段优先证明：

`策略有效`

用户行为改善是重要观察指标，但不是首发版本唯一验收门槛。
