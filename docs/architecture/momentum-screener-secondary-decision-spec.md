## 2. Problem Statement

- 目标用户是 `会看盘但还不会系统化选股的人`；他们通常已经能把候选池收敛到 3 只左右，但分不清谁更值得买、为什么更值得买。
- 当前产品能筛出候选池，但还不能让用户直观判断“这些票选得准不准、明天能不能下手、值不值得信”。
- 当前输出停留在“筛选结果”，没有真正收口到真实目标：从当天强势股里选出最多 3 只，找到次日买点，辅助持仓与卖出决策，最终稳定赚钱。
- 当前页面缺少“为什么选这 3 只、为什么没选其他票、为什么今天该做或不该做”的完整解释链路，导致用户很难建立信任。
- 当前产品没有明确表达策略何时强、何时弱、何时应停用、何时恢复，因此在策略失效期容易误导用户继续出手。
- 当前筛选结果没有把“主线、角色、买点、证据、执行优先级”串成一套完整决策流程，导致候选池和实战之间仍然有断层。
- 当前用户的核心痛点不是“找不到票”，而是“已经能缩到 3 只，但分不清谁更值得买”，并且容易在买点未清晰时提前追高。

## 3. Proposed Solution

- 在现有强势筛选页保留候选池与筛选结果，并新增一个 `二次决策` 视图；`Standard / Aggressive` 继续作为底层候选引擎存在，但不作为用户主心智。
- 页面顶部新增 `今日出手级别 + 一句理由`，级别共五档：`强烈可做 / 可正常出手 / 谨慎出手 / 仅观察 / 今日不做`。
- 五档定义如下：`强烈可做` = 主线极强、3 票都具备清晰买点、市场情绪高涨且赚钱效应明显；`可正常出手` = 主线够强，默认组合中有 2-3 只具备清晰买点；`谨慎出手` = 只有 1 条主线或 2 条弱主线，且只有 1 只票具备清晰买点；`仅观察` = 方向仍在，但还不够放心执行；`今日不做` = 即使有个别票看起来还行，系统也应明确劝退。
- 今日出手级别由 `策略健康 + 主线清晰度 + 默认组合质量` 综合决定，但采用强一票否决；`策略停用` 直接落到 `今日不做`；若 `买点不清晰`，则 `主线极强` 时最多 `仅观察`，否则直接 `今日不做`。
- 系统先识别 `1-2 条主线`，核心依据为主线综合评分；评分由 `板块热度、梯队完整度、资金支持强度` 组成。
- `主线极强` 不采用单纯综合评分直接判定，而采用 `先硬门槛、再看综合分` 的方式。要进入 `主线极强` 判断池，至少必须同时满足 `梯队完整` 与 `强势股密度高` 两个硬门槛，再结合 `资金支持强` 完成最终判定。
- `强势股密度高` 不应只看绝对数量，也不应只看比例，而应同时考虑主线内强势股的 `绝对数量` 与 `相对密度`；其中 `相对密度` 优先级高于绝对数量，即更核心的是该主线是否形成了足够明显的强势集中。
- `梯队完整` 的底层硬前提是：必须存在明确 `龙头核心`。若没有明确龙头核心，即使板块内存在若干强势股，也不能判定为梯队完整。若存在明确龙头核心，但缺少足够好的 `前排换手`，则该主线最多只能判定为 `偏强`，不能升级为 `主线极强`。
- `资金支持强` 的主判定，不以事后赚钱效应为第一依据，而以 `分歧中的承接、回封与回流` 作为硬证据。`持续赚钱效应与增量资金回流` 作为辅助验证项，用于验证主线延续性，而不作为第一性硬门槛。
- `资金支持强` 的成立应采用链路判定，而非单点信号判定，即需依次观察到 `分歧砸盘`、`承接横住`、`回流转强或修复回封`；只有当该链路成立时，才应判定该主线具备真正的 `资金支持强`。
- 若只有 1 条主线成立，默认 3 个名额都可来自该主线；若有 2 条主线，强度接近时按两条线分配名额，若一条明显更强，则允许其占据前两个核心名额。
- 每条主线默认展示 3 个代表股：`龙头核心 / 前排换手 / 观察备选`。Phase 1 的重点执行角色优先围绕 `龙头核心` 与 `前排换手`。
- 页面同时给出默认 `1-3 票组合`，名称为 `主仓 / 次仓 / 观察仓`。通常 `主仓` 偏龙头核心，`次仓` 偏前排换手，`观察仓` 偏观察备选，但允许动态错位。
- `主仓` 的定义是“明天买点最清晰的那只”；因此只要 `前排换手` 的买点比 `龙头核心` 更清晰，就可以直接升为主仓。
- `次仓` 的定义是“进攻性更强、但确定性略弱于主仓”的那只。
- `观察仓` 的定义不是凑数，而是 `主线确认票`；若龙头核心买点不清晰，但仍有主线风向标价值，可以降为观察仓。
- 系统不强行凑满 3 只；若当天只有 `主仓 + 次仓` 够格，就只输出 2 只，第三位留空。
- `主仓 / 次仓 / 观察仓` 为系统正式排序结果，用户默认只能看，不能改写；系统必须对该排序负责。
- 每张推荐股卡片优先回答“为什么它适合放在这个仓位”。信息顺序为：第一句从 `主线视角` 解释其位置；第二句用一句话讲清 `主线地位 + 明天买点/执行理由`；第三层说明它在 3 票组合里的作用。
- 所有未入选股票都要给出 `一个主因` 作为淘汰理由；主因优先级为：`非主线/主线过弱 > 主线内名次不够 > 角色重复 > 买点不清晰 > 近期验证弱`。
- 买点展示采用规则化分层输出，不直接下交易指令；每只票都展示 `优先买入区、触发条件、追高上限、失效位`。
- `龙头核心` 的买点规则优先看 `回踩承接`，若无回踩则看 `高开后强度确认`；`前排换手` 的买点规则优先看 `分歧转一致`，若无则看 `放量/换手确认`。
- `买点清晰` 的核心定义，不是抽象逻辑清楚，而是 `买入区间清楚且可执行`。一只股票若要被判定为 `买点清晰`，至少必须给出一个 `最优买入区`；若还能给出 `次优观察/补买区`，则属于增强信息，但不是硬门槛。`追高上限` 与 `失效位` 仍应展示，但不构成 `买点清晰` 的最低成立条件。
- `最优买入区` 必须锚定 `客观价格参考点` 生成，不能只给模糊判断。若买入区间过宽，则不应判定为 `买点清晰`。Phase 1 先按角色区分阈值：`龙头核心` 的最优买入区最大宽度 `<= 2%`；`前排换手` 的最优买入区最大宽度 `<= 3%`。
- `龙头核心` 的最优买入区，优先围绕 `次日盘中强承接位` 生成，而非简单围绕昨收或前高静态给价。`强承接位` 的判定以组合条件为主：回落至均价线附近后有明显承接、急杀后能横住形成平台、随后重新转强。
- `前排换手` 的最优买入区，优先围绕 `分时均价线附近` 生成。`均价线承接有效` 的判定不以“碰线即反弹”为主，而更强调在均价线附近充分换手后站稳，或短暂跌破后快速拉回；整体更偏向 `充分换手后再上攻` 的结构。
- Buy point 的有效窗口以 `次日开盘后前 60 分钟` 为主；Phase 1 以静态规则为主，后续版本再逐步加入更动态的调整。
- 证据区与推荐卡片拆开呈现。推荐卡片负责结论与执行，证据区统一负责可信度证明。
- 证据区的展示顺序为：先回答 `这条主线最近值不值得做`；再回答 `为什么今天系统敢给这个结论`；再给每只推荐股 `1 个最像的历史案例`。
- 历史相似案例按 `买点结构最像` 选取，而不是先按题材或环境匹配。每个案例默认展示三层：`当时怎么上车`、`买入后 1-2 天赚没赚钱`、`最佳卖点 + 保守卖点参考`。
- 除历史案例外，证据区还应支持查看 `组合验证、角色验证、主线验证` 等多层证据，但这些放在次级区域，不抢主路径。
- 只有在 `强烈可做 / 可正常出手` 两档时，页面才生成 `明日行动清单`。清单按时间顺序组织为：`开盘前 / 开盘后 30 分钟 / 开盘后 60 分钟内`。
- `开盘前` 重点提醒用户先看三只推荐股的预期开盘强弱，明确先盯谁；`开盘后 30 分钟` 重点帮助用户识别谁掉队、先排除不达预期的票；`开盘后 60 分钟内` 必须收口成“今天最终该不该买”的明确结论。
- 如果到开盘后 60 分钟系统判断 `今天不该买`，页面仍保留观察信息，但必须明确标注 `不建议执行买入`。
- 如果到开盘后 60 分钟系统判断 `今天可以买`，则必须明确 `优先关注哪一只、次选哪一只、其余继续观察`；但排序沿用前一晚确定的 `主仓 / 次仓 / 观察仓`，第二天不动态重排。
- 第二天系统的职责不是替用户下单，而是对固定顺序发出信号：`触发了什么买点、为什么触发、失效位在哪里`；若尚未触发，则明确告诉用户 `还差哪些条件才会触发`。
- `低置信度` 的核心，不以数据缺失为第一触发条件，而以 `系统内部关键信号冲突` 为第一触发条件。由于产品采用 `先排序、再给次日执行信号` 的两阶段模式，最优先触发 `低置信度` 的场景是 `昨晚排序强，但次日早盘实际表现不支持`。
- 触发 `低置信度` 的具体表现包括但不限于：`主仓` 在关键时间窗口内迟迟不接近预设买点；`主仓` 的竞价、开盘、承接等表现明显低于预期；`次仓 / 观察仓` 的盘中强度明显反超 `主仓`；总体上，`昨晚排序` 与 `次日实际走法` 出现明显背离。
- 数据延迟、缺失或异常可作为 `低置信度` 的次级触发原因；一旦影响到关键盘中判断，系统同样不应继续输出高确定性的执行结论。
- 一旦进入 `低置信度`，系统不再输出明确的 `建议买` 信号，只保留 `观察信息、低置信度原因说明、仍待验证的条件`。
- `低置信度` 状态不是永久锁死，但只有当 `原排序重新被盘面验证` 时，系统才允许恢复正常置信度与明确买入信号，例如 `主仓` 重新走强、重新接近或进入预设买点、承接与结构修复重新成立。
- 候选替代逻辑只作为系统内部排序与备选生成逻辑，不对用户开放手动改写。其内部优先级为 `同角色替换 > 同主线替换 > 自由替换`；触发顺序为 `买点失效 > 价格偏离过大 > 同角色备选更优`。
- `价格偏离过大` 不能只机械按“偏离最优买入区多少”来判断，最终应以 `综合盈亏比是否明显劣化` 作为判定标准。判定时需同时考虑 `潜在利润空间是否被明显压缩` 与 `潜在风险回撤是否被明显放大`；若两者共同导致该笔交易的综合盈亏比显著变差，则应认定为 `价格偏离过大`。
- 对 `龙头核心`，`价格偏离过大` 可定义为：当前价格相对后续 `回踩分时均线或关键承接位` 的潜在跌幅，已超过 `次日预期溢价空间`。
- 对 `前排换手`，`价格偏离过大` 可定义为满足以下任一条件：当前价格相对 `分时均线` 的偏离度 `> 3%`；从当前价格到 `涨停位` 的日内剩余上涨空间，已不足潜在回撤空间的 `1.5 倍`。
- `价格偏离过大` 的本质不是“票变弱了”，而是“票仍可能强，但当前位置已经不值得追”。
- 因此，当系统判定某只票 `价格偏离过大` 时，不应直接将其从默认组合或主线结构中移除，而应保留其位置并明确标注 `不建议追入`，同时持续观察其后续是否出现 `分歧回踩、均线承接` 或其他使盈亏比重新修复的机会。
- 策略健康采用双窗口：`20 交易日` 判断当前可用性，`60 交易日` 判断结构可信度。`20 + 60` 同时健康时，允许完整强推荐；只有一边健康时，只能给 `1-2` 只强推荐或观察；两边都失效时，策略进入停用状态。
- 策略停用时，页面仍保留 `候选池 + 筛选结果`，但不再给强推荐组合和强买点；同时必须展示 `停用原因 + 观察区 + 恢复条件`。
- 策略恢复采用 `先观察后恢复`：当 `20 日` 先恢复时，只恢复到 `观察/少量推荐`；当 `60 日` 也恢复后，才恢复完整强推荐。

## 4. Technical Constraints

- 本 SPEC 面向 `A 股短线强势股` 场景，不扩展到港股、美股或中长线策略。
- 核心判断必须 `规则驱动`，AI 只负责解释增强，不作为主决策器。
- Phase 1 规则尽量固定，避免把页面做成高度参数化工具，降低复杂度与维护成本。
- Phase 1 继续基于现有强势筛选页演进，不重做独立新产品入口。
- Phase 1 重点是 `T 日筛股 -> T+1 买点辅助`，不在当前版本内完成完整卖出系统。
- Phase 1 的盘中能力以 `页面内状态提示 / 手动查看` 为主，不要求自动下单，也不把系统定位成全自动盘中交易器。
- 盘中信号要真正有用，依赖 `接近实时的高频 / 逐笔级行情数据`，不能仅依赖日线或粗粒度分钟线。
- 若盘中数据延迟、缺失或质量不稳定，系统应允许降级到 `低置信度` 提示，而不是继续输出与正常状态同强度的结论。
- 所有推荐、证据、状态切换都必须在同一页面闭环呈现，避免用户在多个页面间来回跳转。
- 系统必须允许 `只给 1-2 只`、甚至 `不给强推荐`，而不是为了完整性强凑满 3 只。

## 5. Non-goals

- 不做自动交易、自动下单、自动仓位执行。
- 不做完整卖出系统与盘中实时盯盘替代品。
- 不强推 3 只票，不为了“页面好看”硬凑组合。
- 不把 `Standard / Aggressive` 暴露为用户主要决策心智。
- 不把产品做成高自由度量化终端，Phase 1 不开放大量可调参数。
- 不替代用户做最终买不买、买多少、怎么分配总仓位的决定；系统负责 `排序 + 信号 + 证据 + 强烈倾向`，但不替用户完成最终执行裁决。
- Phase 1 不以教学 / 复盘平台为主要目标；历史案例与证据区的首要作用是增强信任与辅助判断，未来可再延展为教学 / 复盘能力。
- 不覆盖港股、美股、波段、中线等其他交易场景。

## 6. Success Criteria

- 用户在一页内就能回答 5 个问题：`今天该不该做`、`为什么给这 1-3 只`、`为什么没选其他票`、`每只票明天怎么等买点`、`这套判断凭什么值得信`。
- 每只推荐股都必须具备：`仓位理由、买点状态、未触发时缺少的条件、触发后失效位`；每只未入选股都必须具备 `一个主淘汰原因`。
- 策略状态必须可解释：`正常 / 谨慎 / 观察 / 停用 / 恢复中` 的切换都有明确条件和页面表达。
- `龙头核心` 的单票成功标准为：近 `20 / 60` 窗口内胜率 `>= 65%`，买入后 `1-2` 个交易日内存在 `>= 2%` 的利润窗口，最大回撤 `<= 3%`。
- `前排换手` 的单票成功标准为：近 `20 / 60` 窗口内胜率 `>= 60%`，买入后 `1-2` 个交易日内存在 `>= 3%` 的利润窗口，最大回撤 `<= 5%`。
- 推荐股相对效果需同时优于基准：相对 `候选池平均` 至少 `+8%`，相对 `同主线其他股票` 至少 `+5%`，相对 `候选池随机选择` 至少 `+12%`。
- 组合验证以 Phase 1 `等权` 为准；默认 3 票组合需满足 `1-2` 个交易日利润窗口 `>= 2%`、最大回撤 `<= 3%`，且至少 `2 / 3` 个股满足各自单票成功标准。
- `20 日窗口` 用于判断“当前还能不能用”；`60 日窗口` 用于判断“这套逻辑是否仍然可信”。任一窗口失衡时，系统只能降级输出，不可继续满配推荐。
- 当策略停用时，系统要敢于明确劝退；当策略恢复时，系统要先恢复到观察 / 少量推荐，再恢复到完整强推荐，不能一步回满。
- 到次日开盘后 `60 分钟内`，系统必须能把结论收口成：`建议买 / 不建议买`，并说明当前是 `主仓触发、次仓触发、其余观察`，或 `保留观察但不建议执行`。
- 用户层的核心北极星之一是：`用户在开盘后 60 分钟内做出明确“买 / 不买”决定的天数明显上升`。
- 用户层的关键行为观察指标之一是：`用户在系统显示“未触发买点”时提前买入的次数下降`。
- 本阶段验收优先级先以 `策略层有效` 为主；用户行为改善是重要观察指标，但不是首发验收的第一门槛。
