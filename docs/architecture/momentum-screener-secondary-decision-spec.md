## 2. Problem Statement

- 目标用户是“会看盘但还不会系统化选股的人”；他们通常已经能把候选池收敛到 3 只左右，但分不清谁更值得买、为什么更值得买。
- 当前产品能筛出候选池，但还不能让用户直观判断“这些票选得准不准、明天能不能下手、值不值得信”。
- 当前输出停留在“筛选结果”，没有真正收口到真实目标：从当天强势股里选出最多 `3` 只，找到次日买点，辅助持仓与卖出决策，最终稳定赚钱。
- 当前页面缺少“为什么选这 3 只、为什么没选其他票、为什么今天该做或不该做”的完整解释链路，导致用户很难建立信任。
- 当前页面把“最近还能不能进攻”“这套主线值不值得信”“今天该不该做”混在一个“策略健康”心智里，既难懂，也容易把系统做得过于保守。
- 当前筛选结果没有把“主线、角色、买点、证据、执行优先级”串成一套完整决策流程，导致候选池和实战之间仍然有断层。
- 当前用户的核心痛点不是“找不到票”，而是“已经能缩到 3 只，但分不清谁更值得买”，并且容易在买点未清晰时提前追高。
- 在不购买股票实时分钟 / 历史分钟独立权限的前提下，系统不能把盘中快照包装成正式分钟级买点；因此 `6000` 积分升级后的核心价值应放在 `主线识别、短线情绪、题材验证、回测诊断`，而不是过度承诺分时承接。

## 3. Proposed Solution

### 3.1 产品总目标

- 在现有强势筛选页保留候选池与筛选结果，并新增一个 `二次决策` 视图。
- 官方生产链路固定为：`全市场统一入口 -> 候选池 -> 全量评分排序 -> Standard 二次决策 -> 页面固定展示 Top30`。
- `Standard` 是唯一官方主引擎；`Aggressive` 只保留为折叠式的进攻补充观察层，不再与 `Standard` 并列为两套官方答案。
- 官方候选池入口固定覆盖 `主板 + 创业板 + 科创板`，统一基线为：`最小涨幅 4% / 最小成交额 2亿 / 最小换手率 2%`。
- 普通用户在官方模式下不再调节入口阈值，也不再调节 `TopN`；页面与导出统一固定为 `Top30`。
- V1.3 在 `6000` 积分数据权限下新增 `主线增强层`：基于题材成分、涨停炸板、涨跌停价和热榜数据，把二次决策从单股排序升级为 `强势股 + 主线 + 情绪 + 角色` 联合判断。
- 系统从“筛结果”升级为“先排序，再给次日执行信号”的两阶段助手。
- 用户默认只能看系统给出的 `主仓 / 次仓 / 观察仓` 结果，不能手动改写排序，以保持系统权威性与回测口径稳定。

### 3.2 今日出手级别与页面主心智

- 页面顶部继续展示 `今日出手级别 + 一句理由`，级别共五档：
  - `强烈可做`
  - `可正常出手`
  - `谨慎出手`
  - `仅观察`
  - `今日不做`
- 新总原则为：
  - **先由当天市场与机会决定能不能做，再用 20/60 判断该用多大力度相信。**
- `今日出手级别` 的主结论先由 `市场环境 × 机会质量` 决定，再由 `20日进攻温度 × 60日结构信任度` 联合校准。
- `20日 / 60日` 只负责风险温度与结构信任折扣，不再单独把系统压成恒定停用。

### 3.3 主线、角色与默认组合

- 系统先识别 `1-2` 条主线，核心依据为主线综合评分。
- 主线综合评分由 `板块热度、梯队完整度、资金支持强度` 组成。
- `主线极强` 不采用单纯综合分直接判定，而采用“先硬门槛、再看综合分”的方式：
  - 至少同时满足 `梯队完整`
  - 且满足 `强势股密度高`
  - 再结合 `资金支持强`
- `强势股密度高` 既看主线内强势股的绝对数量，也看相对密度；相对密度优先级高于绝对数量。
- `梯队完整` 的底层硬前提是存在明确 `龙头核心`；若没有明确龙头核心，即使板块内有若干强势股，也不能判定为梯队完整。
- `资金支持强` 的主判定不以事后赚钱效应为第一依据，而以 `分歧中的承接、回封与回流` 作为硬证据；`持续赚钱效应与增量回流` 作为辅助验证项。
- 若只有 `1` 条主线成立，默认 `3` 个名额都可来自该主线；若有 `2` 条主线，强度接近时按两条线分配名额，若一条明显更强，则允许其占据前两个核心名额。
- 每条主线默认展示 `3` 个代表股：
  - `龙头核心`
  - `前排换手`
  - `观察备选`
- 页面同时给出默认 `1-3` 票组合，名称为：
  - `主仓`
  - `次仓`
  - `观察仓`
- 通常 `主仓` 偏龙头核心，`次仓` 偏前排换手，`观察仓` 偏观察备选，但允许动态错位。
- `主仓` 的定义是“明天买点最清晰的那只”；因此只要 `前排换手` 的买点比 `龙头核心` 更清晰，就可以直接升为主仓。
- `次仓` 的定义是“进攻性更强，但确定性略弱于主仓”的那只。
- `观察仓` 的定义不是凑数，而是 `主线确认票`；若龙头核心买点不清晰，但仍有主线风向标价值，可以降为观察仓。
- 系统不强行凑满 `3` 只；若当天只有 `主仓 + 次仓` 够格，就只输出 `2` 只，第三位留空。

### 3.4 推荐卡片、落选说明与买点输出

- 每张推荐股卡片优先回答“为什么它适合放在这个仓位”。
- 推荐卡片的信息顺序为：
  - 第一句从 `主线视角` 解释其位置
  - 第二句用一句话讲清 `主线地位 + 明天买点 / 执行理由`
  - 第三层说明它在 `3` 票组合里的作用
- 所有未入选股票都要给出 `一个主因` 作为淘汰理由；主因优先级为：
  - `非主线 / 主线过弱`
  - `主线内名次不够`
  - `角色重复`
  - `买点不清晰`
  - `近期验证弱`
- 买点展示采用规则化分层输出，不直接下交易指令；每只票都展示：
  - `优先买入区`
  - `触发条件`
  - `追高上限`
  - `失效位`
- `龙头核心` 的买点规则优先看 `回踩承接`，若无回踩则看 `高开后强度确认`。
- `前排换手` 的买点规则优先看 `分歧转一致`，若无则看 `放量 / 换手确认`。
- `买点清晰` 的核心定义，不是抽象逻辑清楚，而是 `买入区间清楚且可执行`。
- 一只股票若要被判定为 `买点清晰`，至少必须给出一个 `最优买入区`；若还能给出 `次优观察 / 补买区`，则属于增强信息，但不是硬门槛。
- `龙头核心` 的最优买入区优先围绕 `次日盘中强承接位` 生成；`前排换手` 的最优买入区优先围绕 `分时均价线附近` 生成。
- Buy point 的有效窗口以 `次日开盘后前 60 分钟` 为主；Phase 1 以静态规则为主，后续版本再逐步加入更动态的调整。

### 3.5 证据区与历史案例

- 证据区与推荐卡片拆开呈现。推荐卡片负责结论与执行，证据区统一负责可信度证明。
- 证据区的展示顺序为：
  - 先回答 `这条主线最近值不值得做`
  - 再回答 `为什么今天系统敢给这个结论`
  - 再给每只推荐股 `1` 个最像的历史案例
- 历史相似案例按 `买点结构最像` 选取，而不是先按题材或环境匹配。
- 每个案例默认展示三层：
  - `当时怎么上车`
  - `买入后 1-2 天赚没赚钱`
  - `最佳卖点 + 保守卖点参考`
- 除历史案例外，证据区还应支持查看：
  - `组合验证`
  - `角色验证`
  - `主线验证`
- 这些放在次级区域，不抢主路径。

### 3.6 新总闸门

#### 3.6.1 用户侧命名

- 页面用户侧彻底移除 `策略健康` 旧词。
- 统一拆成两张独立卡：
  - `20日进攻温度`
  - `60日结构信任度`
- 两张卡都展示：
  - 一句结论
  - 分数和状态
  - 一句解释
- 顶部与 `今日出手级别` 并排摘要两张卡的结论。
- `20日 / 60日` 不再作为简单硬停用闸门，而是用于判断“今天这套结论该用多大力度相信”。
- 若当天仍可做，但 `60日结构信任度 = 存疑`，动作级别不自动降到 `今日不做`，只在顶部展示信任折扣提示。

#### 3.6.2 20日进攻温度

- `20日进攻温度` 只负责回答“最近 20 个交易日，短线强势股是否仍适合主动进攻”。
- 评分不再使用单一命中率硬切，改为综合观察：
  - 主仓 T+2 正收益率，权重 `30%`
  - 官方 Top3 平均利润窗口，权重 `25%`
  - 买点触发率，权重 `15%`
  - 平均最大回撤，权重 `15%`
  - 错杀机会率，权重 `15%`
- 回撤口径允许强势股存在正常波动：`Standard` 主链路可把 `5%` 左右平均回撤视为正常风险区，`Aggressive` 补充层允许约 `10%` 个股波动预期但不得推翻官方总闸门。
- 用户侧状态词固定为：
  - `热`
  - `温`
  - `冷`
  - `冰`
- 状态语义如下：
  - `热`：最近进攻环境顺畅，不压级，允许出现 `强烈可做`
  - `温`：仍可进攻，不硬压级，但文案提示控制节奏
  - `冷`：近期反馈降温，默认降低进攻力度，优先保留主仓或少量推荐
  - `冰`：近期进攻反馈明显变差，除非当天市场和机会都极强，否则最高只保留观察

#### 3.6.3 60日结构信任度

- `60日结构信任度` 只负责回答“主线识别、角色分配和默认组合框架最近是否仍值得相信”，不再直接硬压当天动作。
- 评分重点看结构增益，而不是简单复用 20 日胜率：
  - 官方 Top3 相对候选池 Top10 的超额收益
  - 官方 Top3 相对原始排序 Top3 的超额收益
  - 主仓相对次仓 / 观察仓的稳定优势
  - 龙头核心、前排换手、观察备选的角色稳定性
  - 强市 / 中性市 / 弱市下的市场分层适配度
  - 被限制后的错过机会率
- 用户侧状态词固定为：
  - `可信`
  - `可参考`
  - `存疑`
  - `失真`
- 状态语义如下：
  - `可信`：结构有稳定增益，不额外压级
  - `可参考`：结构仍有参考价值，但优势不够稳定
  - `存疑`：结构增益不稳定，限制强信任表达
  - `失真`：主线或角色框架已明显不能解释结果，只在与 `20日冰` 叠加时触发硬停用

#### 3.6.4 市场环境

- `市场环境` 回答的问题不是“大盘是不是涨”，而是：
  - **市场今天愿不愿意继续为强势股付溢价。**
- 采用双层样本池：
  - `昨日二次决策 Top3`：看核心溢价
  - `昨日候选池 Top10`：看广度溢价
- `核心有溢价` 的条件为：
  - 昨日 `Top3` 中，今天至少 `1` 只先满足买点触发
  - 且 `T+1/T+2 利润窗口 >= 2.0%`
- `广度达标` 的条件为：
  - 昨日候选池 `Top10` 命中率 `>= 30%`
  - 且平均利润窗口 `>= 2.0%`
- 三档结论如下：
  - `强`：核心有溢价，且广度达标
  - `中等`：只好一边
  - `弱`：两边都不行

#### 3.6.5 机会质量

- `机会质量` 回答的问题是：
  - **今天系统手上的这批票，是否足够适合出手。**
- 按以下顺序判断：
  - 买点清晰度
  - 默认组合盈亏比
  - 主线集中度
- 买点清晰度按默认组合中“买点清晰 / 可执行”的数量分档：
  - `3只清晰 = 强`
  - `2只清晰 = 中上`
  - `1只清晰 = 中`
  - `0只清晰 = 弱`
- 默认组合盈亏比口径为：
  - `预期利润空间 vs 预期失效空间`
- 盈亏比聚合方式为：
  - `主仓优先 + 组合轻修正`
- 主仓最低门槛为：
  - `预期利润空间 >= 预期失效空间的 1.5 倍`
- 主线集中度第一版判断为：
  - 默认组合里至少 `2` 只来自第一主线
- 合成规则如下：
  - `3只清晰`
    - 默认 `强`
    - 只有主仓盈亏比不过线时，才允许下调
  - `2只清晰`
    - 默认 `中上`
    - 只有“主仓盈亏比过线 + 主线集中度达标”时，才允许上调到 `强`
  - `1只清晰`
    - 默认 `中`
    - 主仓盈亏比过线，则维持 `中`
    - 不过线，则降为 `弱`
  - `0只清晰`
    - 固定 `弱`
    - 不允许被其他条件抬高

#### 3.6.6 主矩阵与20/60联合校准

- `今日出手级别` 的主矩阵先由 `市场环境 × 机会质量` 决定：

| 市场环境 \\ 机会质量 | 强 | 中上 | 中 | 弱 |
| --- | --- | --- | --- | --- |
| 强 | 强烈可做 | 可正常出手 | 谨慎出手 | 仅观察 |
| 中等 | 可正常出手 | 谨慎出手 | 仅观察 | 今日不做 |
| 弱 | 谨慎出手 | 仅观察 | 今日不做 | 今日不做 |

- 主矩阵给出结果后，再由 `20日进攻温度 × 60日结构信任度` 做力度校准：

| 20日进攻温度 \\ 60日结构信任度 | 可信 | 可参考 | 存疑 | 失真 |
| --- | --- | --- | --- | --- |
| 热 | 不压级，可强推 | 不压级，提示信任折扣 | 最高 `可正常出手` | 最高 `谨慎出手` |
| 温 | 不压级，文案收敛 | 最高 `可正常出手` | 最高 `谨慎出手` | 最高 `仅观察` |
| 冷 | 最高 `谨慎出手`，优先主仓 | 最高 `谨慎出手`，优先主仓 | 最高 `仅观察` | 最高 `仅观察` |
| 冰 | 最高 `仅观察` | 最高 `仅观察` | 最高 `今日不做` | `系统停用 / 今日不做` |

- 若 `市场环境 = 强` 且 `机会质量 = 强`，`20日进攻温度 = 冷` 时仍可保留到 `谨慎出手`。
- 若 `60日结构信任度 = 存疑`，但主仓买点清晰且主仓历史表现仍强，页面可以输出 `谨慎出手`，但不得使用“强烈可做”话术。
- 若 `20日进攻温度 = 冰`，系统必须明确提示“仅允许观察，除非出现极端强市场与极清晰买点”。

#### 3.6.7 停用与恢复

- `今日不做` 是单日结论，不等于系统长期停用。
- `系统停用` 只有在以下条件下触发：
  - 连续 `5` 个交易日
  - `20日进攻温度 = 冰`
  - 且 `60日结构信任度 = 失真`
  - 且当天 `市场环境 / 机会质量` 没有同时达到 `强`
- 退出停用的条件为：
  - `20日进攻温度` 回到 `冷` 或更高
  - 且当天 `市场环境` 不是 `弱`
- 退出停用后，只恢复到：
  - `仅观察`
  - 或最多 `谨慎出手`
- 当 `20日进攻温度` 回到 `温` 或 `热` 时，允许恢复到 `可正常出手`。
- 重新允许 `强烈可做` 的条件为：
  - `20日进攻温度 = 热`
  - `60日结构信任度` 不为 `失真`
  - `市场环境 = 强`
  - `机会质量 = 强`

### 3.7 明日行动清单与盘中职责

- 只有在 `强烈可做 / 可正常出手` 两档时，页面才生成 `明日行动清单`。
- 行动清单按时间顺序组织为：
  - `开盘前`
  - `开盘后 30 分钟`
  - `开盘后 60 分钟内`
- `开盘前` 重点提醒用户先看三只推荐股的预期开盘强弱，明确先盯谁。
- `开盘后 30 分钟` 重点帮助用户识别谁掉队、先排除不达预期的票。
- `开盘后 60 分钟内` 必须收口成“今天最终该不该买”的明确结论。
- 如果到开盘后 `60` 分钟系统判断 `今天不该买`，页面仍保留观察信息，但必须明确标注 `不建议执行买入`。
- 如果到开盘后 `60` 分钟系统判断 `今天可以买`，则必须明确：
  - `优先关注哪一只`
  - `次选哪一只`
  - `其余继续观察`
- 第二天系统的职责不是替用户下单，而是对固定顺序发出信号：
  - `触发了什么买点`
  - `为什么触发`
  - `失效位在哪里`
  - 若尚未触发，则明确说明 `还差哪些条件才会触发`

### 3.8 低置信度与替换逻辑

- `低置信度` 的核心，不以数据缺失为第一触发条件，而以 `系统内部关键判断冲突` 为第一触发条件。
- 最优先触发场景是：
  - `昨晚排序强`
  - 但 `次日早盘实际表现不支持`
- 一旦进入 `低置信度`，系统不再输出明确的 `建议买` 信号，只保留：
  - `观察信息`
  - `低置信度原因说明`
  - `仍待验证的条件`
- `低置信度` 不是永久锁死，只有当“原排序重新被盘面验证”时，系统才允许恢复正常置信度与明确信号。
- 候选替换逻辑只作为系统内部排序与备选生成逻辑，不对用户开放手动改写。
- 内部替换优先级为：
  - `同角色替换`
  - `同主线替换`
  - `自由替换`
- 触发顺序为：
  - `买点失效`
  - `价格偏离过大`
  - `同角色备选更优`
- `价格偏离过大` 的本质不是“票变弱了”，而是“票可能仍强，但当前位置已经不值得追”。
- 当系统判定某只票 `价格偏离过大` 时，不应直接从默认组合中移除，而应保留其位置并明确标注 `不建议追入`。

### 3.9 官方入口与 Aggressive 补充观察层

- `Top30` 只是官方页面展示、导出与回测对齐基线；二次决策本身始终基于 `完整排序集`，而不是基于页面当前展示数量继续挑票。
- `Standard` 负责官方 `今日出手级别`、官方 `主仓 / 次仓 / 观察仓`、官方行动清单与官方回测。
- `Aggressive` 默认放入折叠区，只有在补出 `不在 Standard 官方 Top3 内的新票`，且该票同时满足 `高进攻度 + 买点相对清晰 + 不推翻 Standard 总闸门` 时，页面才提示可展开查看。
- `高进攻度` 定义为：`弹性高 + 主线里有地位 + 风险不过红线`；其中风险红线至少排除 `明显追高 / 没有买点区间 / 已接近失效位` 三类硬伤。
- `Aggressive` 的“买点相对清晰”比 `Standard` 宽半档：允许 `等待触发` 进入补充观察，但前提必须同时具备 `买点区间 + 触发条件 + 非明显追高`。
- `Aggressive` 只展示新增补充票，最多 `2` 只，按 `进攻弹性` 排序，输出完整观察卡：`进攻理由 / 主线角色 / 买点区间 / 触发条件 / 失效位`。
- `Aggressive` 可进入独立的 `进攻观察清单`，但必须与 `Standard 官方行动清单` 分开展示，并始终明确标注 `仅补充观察，不纳入官方组合`。
- 即使 `Aggressive` 补充票次日先触发，也不能升格替代 `Standard` 官方顺序；若 `Standard` 判为 `仅观察 / 今日不做`，`Aggressive` 也只能补充观察，不改变官方结论。
- 官方复盘与官方回测只回放 `Standard` 链路；`Aggressive` 只保留 `补充增益率` 诊断，不再作为独立官方回测画像。

### 3.10 V1.3 主线增强层

- V1.3 面向 `6000` 积分数据权限，不依赖股票实时分钟、股票历史分钟、Level-2 或逐笔成交。
- V1.3 新增的数据输入包括：
  - `stk_limit`：涨停价、跌停价、涨停距离、追高红线和剩余空间。
  - `limit_list_d`：涨停、跌停、炸板、连板、封单金额、开板次数。
  - `dc_concept`：东方财富题材强度、热度、涨停数、主力净流入、领涨股和排名。
  - `moneyflow_ind_dc`：行业 / 概念 / 地域板块资金流，提供主力净额、超大单 / 大单结构和板块排名。
  - `dc_member / dc_index / dc_daily`：东方财富板块成分、板块基础信息和板块日行情，用于股票到真实强板块映射和历史回放。
  - `kpl_list`：开盘啦涨停原因和题材标签，用于解释打板资金选择的语义。
  - `moneyflow_dc / moneyflow_ths`：个股资金流，作为第二阶段增强，用于判断主线内个股承接。
  - `cyq_perf / cyq_chips`：筹码分布，作为第二阶段增强，用于追高风险和上方压力辅助。
  - `ths_member`：股票到同花顺概念 / 题材 / 主线的成分映射。
  - `ths_hot`：热门股、热门概念和盘中关注度辅助证据。
  - `realtime_quote`：当前价、开盘价、最高价、最低价和盘口快照，作为低置信度盘中辅助。
- V1.3 的主线识别流程为：`真实板块强度 -> 股票 / 板块映射 -> 父题材归并 -> 候选池覆盖 -> 主线强度评分`。
- 主线评分由 `主线密度、涨停强度、炸板风险、资金热度、延续反馈` 组成。
- 页面新增 `主线雷达`：展示当日最强 `1-2` 条主线，以及主线强度、候选池占比、涨停数、炸板风险、热榜支撑和代表股。
- 主线雷达不得只展示 `886089.TI`、`700457.TI` 这类原始概念代码；必须翻译为用户可理解的题材 / 板块名称，并展示数据来源。
- 若 `dc_concept / moneyflow_ind_dc / dc_member` 指向同一资金方向，优先以该真实强板块作为主线结论，`ths_hot` 只作为辅助关注度证据。
- 父题材归并必须支持把碎片概念聚合为可复盘的大题材，例如将 `锂电池概念 / 电池技术 / 锂矿概念 / 固态电池` 归并为 `电池`。
- 对于 `多氟多 / 天华新能 / 恩捷股份 / 天赐材料 / 盛新锂能 / 天齐锂业` 这类同产业链候选，如果真实板块强度和成分映射支持，系统应能归因为 `电池` 主线，而不是分散成不可理解的概念代码。
- 若真实板块强度数据不可用，系统可降级到 `ths_member + ths_hot + 父题材词库`，但必须降低置信度并显示降级原因。
- 总闸门新增 `短线情绪` 模块，情绪结论分为：
  - `高涨`
  - `可做`
  - `分歧`
  - `退潮`
- 短线情绪参与 `今日出手级别` 校准：
  - `高涨` 可上调一档，但不得绕过买点和风险边界。
  - `分歧` 限制强信任表达。
  - `退潮` 场景除非主线和机会质量极强，否则最高只保留观察。
- `主仓 / 次仓 / 观察仓` 的收口必须结合题材内地位：
  - `龙头核心` 需体现主线带动性、涨停 / 连板 / 成交额地位和近期延续反馈。
  - `前排换手` 需体现主线内排序、健康成交额 / 换手率和非后排跟风属性。
  - `观察备选` 应体现主线确认、补涨潜力或风向标价值，而不是简单第三名。
- V1.3 回测必须新增失败归因，至少覆盖：
  - `候选池偏差`
  - `主线识别错误`
  - `角色识别错误`
  - `情绪环境错误`
  - `价格位置错误`
  - `总闸门过紧`
  - `总闸门过松`
- AI 点评只能解释规则层给出的结构化证据，不得用 LLM 替代主线评分、短线情绪或官方 Top3 决策。

## 4. Technical Constraints

- 本 SPEC 面向 `A 股短线强势股` 场景，不扩展到港股、美股或中长线策略。
- 核心判断必须 `规则驱动`，AI 只负责解释增强，不作为主决策器。
- Phase 1 规则尽量固定，避免把页面做成高度参数化工具，降低复杂度与维护成本。
- Phase 1 继续基于现有强势筛选页演进，不重做独立新产品入口。
- Phase 1 重点是 `T 日筛股 -> T+1 买点辅助`，不在当前版本内完成完整卖出系统。
- Phase 1 的盘中能力以 `页面内状态提示 / 手动查看` 为主，不要求自动下单，也不把系统定位成全自动盘中交易器。
- 盘中信号要真正有用，依赖 `接近实时的高频 / 逐笔级行情数据`；若实时数据质量不足，则必须允许系统降级到 `低置信度` 提示。
- V1.3 在仅有 `6000` 积分权限且未开通分钟线权限时，盘中能力必须降级为 `盘中快照辅助`，不得宣称完成分钟级分时承接、VWAP 承接或严格买点触发。
- V1.3 可使用 `stk_limit / limit_list_d / dc_concept / moneyflow_ind_dc / dc_member / dc_index / dc_daily / kpl_list / ths_member / ths_hot / realtime_quote` 增强主线、情绪和解释链路，但所有这些输入都必须保留数据时间与降级状态。
- `dc_concept / moneyflow_ind_dc / dc_member` 是真实板块强度 Provider 的优先输入；`ths_member / ths_hot` 是辅助输入，不得在真实板块数据可用时反向覆盖主线结论。
- 系统内部计算的强度分必须标注为系统分；除非数据源明确提供同名字段，不得宣称复刻开盘啦 App 的官方强度分。
- 所有推荐、证据、状态切换都必须在同一页面闭环呈现，避免用户在多个页面间来回跳转。
- 系统必须允许 `只给 1-2 只`、甚至 `不给强推荐`，而不是为了完整性强凑满 `3` 只。
- `20日进攻温度` 与 `60日结构信任度` 在用户侧必须独立展示，不能再合并回一个“策略健康”总词。
- 官方模式的入口阈值固定为 `4 / 2亿 / 2%`，页面展示与导出固定为 `Top30`，普通用户不再调整入口阈值或展示数量。
- 官方回测只回放 `Standard` 官方链路；`Aggressive` 只保留补充观察与诊断职责，不再作为平行官方结果运行。

## 5. Non-goals

- 不做自动交易、自动下单、自动仓位执行。
- 不做完整卖出系统与盘中实时盯盘替代品。
- 不强推 `3` 只票，不为了“页面好看”硬凑组合。
- 不把 `Standard / Aggressive` 暴露为用户主要决策心智。
- 不把产品做成高自由度量化终端，Phase 1 不开放大量可调参数。
- 不让普通用户在官方模式下修改入口阈值、`TopN` 或通过切换画像来改变官方基线。
- 不把 `Aggressive` 做成第二套官方组合、第二套官方行动清单或第二套官方回测结果。
- V1.3 不做分钟级正式买点触发，不做分时均线 / VWAP 承接确认，不把实时快照包装成高置信度盘中信号。
- V1.3 不承诺完全复刻第三方 App 的专有板块强度算法；系统只接入可合法获取的数据源，并输出自身可解释的主线强度分。
- 不替代用户做最终买不买、买多少、怎么分配总仓位的决定；系统只提供 `排序 + 信号 + 证据 + 强烈倾向`，但不替用户完成最终执行裁决。
- Phase 1 不以教学 / 复盘平台为主要目标；历史案例与证据区的首要作用是增强信任与辅助判断，后续再考虑向教学 / 复盘能力延展。
- 不覆盖港股、美股、波段、中线等其他交易场景。

## 6. Success Criteria

- 用户在一页内就能回答 5 个问题：
  - 今天该不该做
  - 为什么给这 `1-3` 只
  - 为什么没选其他票
  - 每只票明天怎么等买点
  - 这套判断凭什么值得信
- 每只推荐股都必须具备：
  - 仓位理由
  - 买点状态
  - 未触发时缺少的条件
  - 触发后失效位
- 每只未入选股都必须具备 `一个主淘汰原因`。
- 用户侧不再出现单一的“策略健康”总词；必须拆成：
  - `20日进攻温度`
  - `60日结构信任度`
- 两张卡都必须具备：
  - 分数
  - 状态
  - 一句解释
  - 明确的切换条件
- `20日进攻温度` 的用户心智必须稳定为“最近短线强势股是否适合主动进攻”，而不是“默认组合最近考得好不好”。
- `60日结构信任度` 的用户心智必须稳定为“主线、角色和组合框架是否仍值得信”，而不是“今天还能不能出手”。
- `60日结构信任度 = 存疑` 时，若当天仍可做，页面必须展示明确的信任折扣提示，但不自动降成 `今日不做`。
- `20日进攻温度 = 冷` 时，系统仍然允许在“市场环境强 + 机会质量强”的场景下给出 `谨慎出手`，避免过度保守。
- `系统停用` 必须与 `今日不做` 区分展示；`系统停用` 只在连续 `5` 个交易日出现 `20日冰 + 60日失真` 且当天机会不强时才成立。
- 到次日开盘后 `60` 分钟内，系统必须能把结论收口成：
  - `建议买`
  - `不建议买`
  - `保留观察但不建议执行`
- 官方模式下同一交易日的结果必须锚定在统一入口 `4 / 2亿 / 2%` 与固定 `Top30` 基线上，不能再因展示数量或画像切换导致官方结论漂移。
- 用户必须能清楚区分：`Standard` 是官方主结论，`Aggressive` 只是折叠式补充观察；即使补充票先触发，也不改写官方顺序。
- V1.3 页面必须能解释：今日最强主线是什么、主线强度来自哪些证据、短线情绪处于哪一档、官方 Top3 为什么属于这些角色。
- V1.3 页面必须能回答：今天资金主要去了哪些强势板块、这些板块覆盖了候选池哪些股票、系统为什么把它们归并为同一父题材。
- V1.3 回测必须能输出失败归因，而不是只输出收益结果；至少要区分主线、情绪、角色、价格位置和总闸门问题。
- V1.3 回测必须能比较“真实强板块覆盖日期”和“主线不清晰日期”的官方 Top3 表现，并给出主线识别是否带来增益的诊断。
- 当真实板块强度 Provider 不可用时，强势筛选主链路仍应返回结果，并明确显示主线识别降级。
- V1.3 盘中模块必须明确标注 `快照辅助` 与置信度，不能输出分钟级承接已确认或建议买入类表达。
- V1.4 起，回测主胜率统一为 `短线延续合格率`：`T+1 收盘价 > T+1 开盘价`，且 `T+2 最高价 > T+1 收盘价`。它用于判断系统选股方向是否具备次日延续与后日兑现窗口。
- `T+2 利润窗口`、`T+2 最大回撤`、`买点触发率` 保留为执行质量与风险指标，不再单独作为主胜率定义。
- 用户层的核心北极星之一是：
  - `用户在开盘后 60 分钟内做出明确“买 / 不买”决定的天数明显上升`
- 用户层的关键行为观察指标之一是：
  - `用户在系统显示“未触发买点”时提前买入的次数下降`
- 本阶段验收优先级先以 `策略层有效` 为主；用户行为改善是重要观察指标，但不是首发验收的第一门槛。
