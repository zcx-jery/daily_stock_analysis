## 2. 产品概述

### 2.1 本次设计的是什么功能

在强势筛选页面的关键窗口中，增加**基于 LLM 的 AI 点评能力**，让用户可以从纯数字打分 → 自然语言深度分析。

本功能在产品上的准确定义是：

> **AI 点评 = 强势筛选的解释层与追问层，不是新的决策引擎。**

它的职责是：

1. 把规则引擎已经产出的结论翻译成用户能快速理解的自然语言
2. 基于已有筛选结论做补充分析、对比、风险提示和追问延展
3. 通过工具获取外部数据，为规则结论提供更多背景信息

它**不负责**：

1. 推翻规则引擎的原始结论
2. 在盘中重排主仓 / 次仓 / 观察仓
3. 覆盖 `今日不做`、`偏离过大` 等总闸门
4. 变成新的独立交易裁判

四个窗口分别是：

| 窗口 | 位置 | 触发按钮 | 优先级 |
|------|------|----------|--------|
| **候选股 AI 点评** | 详情抽屉内，维度拆解上方 | "AI 点评" | **V1 主入口** |
| **二次决策综合建议** | 二次决策面板顶部 | "AI 综合建议" | **V1 主入口** |
| **盘中信号 AI 解读** | 盘中信号面板底部 | "AI 盘中解读" | V1 次入口 |
| **落选说明 AI 分析** | 落选说明区域底部 | "AI 综合分析" | V1 次入口 |

每个窗口的 AI 点评都接入**同一个对话面板**（右侧弹出，占约 50% 宽度），面板内部维护**按点评对象划分的独立会话**，支持继续追问。

V1 虽然保留四个入口，但用户主路径应明确聚焦在：

1. **候选股 AI 点评**：回答“这只票为什么强 / 风险在哪 / 明天该怎么等”
2. **二次决策 AI 综合建议**：回答“今天到底做不做 / 先盯谁 / 为什么”

### 2.2 为了解决用户什么需求

当前强势筛选页面的核心问题是：**给用户一堆数字和状态标签，但缺少"翻译"和"综合判断"。**

具体痛点：

1. **维度拆解看不懂** — 用户看到"资金承接 2/20 (10%)"，知道低，但不知道"低到多严重、意味着什么"
2. **二次决策结论太机械** — "今日不做"四个字，用户不知道是"完全放弃"还是"观察就好"
3. **盘中信号只有状态标签** — "已触发/等待确认/偏离过大"，用户不知道下一步具体怎么做
4. **落选原因太笼统** — "非主线/主线过弱"，用户不知道这只票到底差在哪里

**AI 点评解决的是"从规则结论到用户理解"的最后一公里：**
- 用自然语言把规则引擎的输出翻译成可理解、可执行的建议
- 让 LLM 调用工具获取更多实时数据（行情、新闻、板块），做更深入的判断
- 用户可以在对话中继续追问，形成"分析 → 追问 → 更深分析"的闭环

### 2.3 设计原则

| 原则 | 说明 |
|------|------|
| **规则先于 AI** | 页面先展示规则结论，AI 只能解释、补充、对比，不能反向改写规则结果 |
| **LLM 不改规则** | AI 点评不修改、不覆盖规则引擎的任何结论，只做解释和建议 |
| **全部手动触发** | 所有 AI 点评按钮均为手动点击触发，不自动调用 |
| **工具调用必须** | LLM 点评必须支持工具调用（行情、新闻、板块分析等） |
| **不缓存输出** | 每次触发都重新调用 LLM，不使用缓存 |
| **独立会话** | 每个点评对象的对话独立持久化，不混合 |
| **盘中边界更硬** | AI 盘中解读不能重排昨晚顺序、不能推翻 `今日不做`、不能为“偏离过大”给出追入建议 |
| **先看旧结论，再决定重跑** | 重开面板时默认回到上次会话，用户主动点击“基于最新数据重新分析”才触发新一轮点评 |
| **双轨执行统一** | AI 执行守卫必须和 V1.3 双轨制验收合同一致，低开不是自动劝退理由，必须结合日内修复确认 |

### 2.4 Recovery Support（Track B Support）

V1.3 Gold 版本开始，AI 点评必须正式支持双轨制可交易合同，避免出现“回测承认低开修复，但 AI 仍按旧口径劝退”的认知冲突。

AI 执行守卫必须遵守：

1. **Track A 动量延续**：`T+1 Open >= T0 Close * 0.99` 且 `T+1 Close > T+1 Open`，属于正常开盘承接确认。
2. **Track B 低开修复**：若 `T+1 Open < T0 Close * 0.99`，AI 不能仅因低开给出强制 `Abandon` / `Caution`；应提示观察开盘后 30 分钟是否出现带量反转并重新站上 `T0 Close`。
3. **Reversal Entry 引导**：低开场景下，只有当分时强度收复 `T0 Close`、收盘强于开盘且后续仍满足滑点调整后的 T+2 退出缓冲时，才可描述为“低开转强观察有效”。
4. **无效修复边界**：若低开后无法收回 `T0 Close`，或开盘后 30 分钟高点始终无法突破，AI 应提示 `Reduce Position` / 降仓或继续仅观察。

对 `RETAINED_LEADER_DIVERGENCE`、`mainline_position_churn`、潜在 `Mainline_Churn` 标的，AI 必须允许 **Volatility Gap（波动缺口）**，优先给出“先看 30 分钟承接与带量反转”的执行提示，而不是旧版“一低开就放弃”的硬口径。

## 3. 目标用户

### 3.1 核心用户

- A 股短线交易用户
- 会使用强势筛选功能，但需要更深入的解读
- 不满足于只看分数和标签，想知道"为什么"和"怎么做"
- 有追问习惯，喜欢和 AI 讨论交易思路

### 3.2 使用场景

| 场景 | 用户行为 |
|------|----------|
| 收盘后复盘 | 看筛选结果 → 展开详情 → 点击 AI 点评 → 了解每只票的优劣 → 追问对比 |
| 制定明日计划 | 看二次决策 → 点击 AI 综合建议 → 获取操作指南 → 追问"如果板块变了怎么办" |
| 盘中盯盘 | 点击刷新盘中信号 → 点击 AI 盘中解读 → 获取当前时刻的解释与风控提醒 |
| 研究落选票 | 看落选说明 → 点击 AI 综合分析 → 了解为什么高分票被筛掉、哪些只是暂时不合适 |

### 4.2 四个点评窗口的设计

#### 4.2.0 入口优先级与上线顺序

为了避免强势筛选页变成“到处都能问 AI、但没有主路径”，V1 必须明确入口优先级：

| 优先级 | 入口 | 产品目标 |
|--------|------|----------|
| **主入口** | 候选股 AI 点评 | 帮用户理解“这只票为什么强、风险在哪、明天怎么等” |
| **主入口** | 二次决策 AI 综合建议 | 帮用户理解“今天做不做、为什么、先盯谁” |
| 次入口 | 盘中信号 AI 解读 | 帮用户理解“当前状态意味着什么”，但不替代盘中执行纪律 |
| 次入口 | 落选说明 AI 分析 | 帮用户理解“为什么没选它、哪些值得继续观察” |

产品上应优先保证主入口的完成度和稳定性，次入口可以更克制。

#### 4.2.1 候选股 AI 点评

**触发位置**：候选股详情抽屉内，维度拆解表格上方

```
┌───────────────────────────────────────────────────────────┐
│  石大胜华 · 603026.SH                              [×]   │
├───────────────────────────────────────────────────────────┤
│                                                           │
│  指标卡片：总分 61.0 | 排序分 63.1 | 可买分 70.0 | ...    │
│                                                           │
│  ┌─────────────────────────────────────────────────────┐ │
│  │  🤖 AI 点评                                   [展开] │ │
│  └─────────────────────────────────────────────────────┘ │
│  ↑ 用户点击"展开"按钮                                    │
│  ↓                                                       │
│  右侧弹出对话面板，自动发送点评请求                       │
│                                                           │
│  维度拆解：                                                │
│  ├── 强势确认 30.0/30.0 (100%)                           │
│  ├── 资金承接 2.0/20.0 (10%)                             │
│  └── ...                                                  │
│                                                           │
└───────────────────────────────────────────────────────────┘
```

**AI 点评内容要点**：
1. **一句话结论**：这只票当前是否值得重点关注
2. **为什么入选**：核心优势与最强证据
3. **维度翻译**：把强项 / 弱项翻译成自然语言
4. **最大风险**：当前最不能忽视的风险点
5. **明日触发条件**：什么情况下才值得升级关注
6. **明日放弃条件**：什么情况下直接不做

首条回答必须优先围绕这 6 点组织，不能自由发散。

**对话面板标题**：`AI 点评 · 石大胜华 (603026.SH)`

#### 4.2.2 二次决策 AI 综合建议

**触发位置**：二次决策面板顶部，与"今日不做"等结构化结论并列

```
┌───────────────────────────────────────────────────────────┐

│                                                           │

│  │  🔴 今日不做                           [🤖 AI 建议] │ │

│  └─────────────────────────────────────────────────────┘ │
│  ↑ 用户点击"AI 建议"按钮                                 │
│  ↓                                                       │
│  右侧弹出对话面板，自动发送综合建议请求                   │
│                                                           │
│  策略健康：停用                                           │
│  默认组合：主仓 利通电子 | 次仓 圣阳股份 | 观察 江海股份 │
│  主线识别：电力设备 73.6 | 电子 73.0                      │
│  落选说明：8 只未入选                                     │
│                                                           │
└───────────────────────────────────────────────────────────┘
```

**AI 综合建议内容要点**：
1. **今天到底该不该做**：先明确“做 / 不做 / 仅观察”
2. **为什么**：规则总闸门、策略健康和主线状态分别怎么影响结论
3. **先盯谁**：主仓 / 次仓 / 观察仓各自的角色和优先级
4. **哪些信号才允许升级执行**
5. **哪些情况直接劝退**

这类回答必须先复述规则结论，再做 AI 解释，不能直接跳到自由建议。

**对话面板标题**：`AI 综合建议 · 二次决策 (Aggressive)`

**AI 盘中解读内容要点**：
1. 当前交易时段的整体判断（"现在这个时间点最该关注什么"）
2. 各候选股的实时状态解读（解释标签，不重排顺序）
3. 当前时刻的风险提示
4. 接下来 60 分钟的关注重点

盘中解读必须遵守三条硬边界：

1. 不能重排昨晚的 `主仓 / 次仓 / 观察仓`
2. 不能推翻 `今日不做`
3. 对已判定 `偏离过大` 的标的，不能给出追入型建议

**对话面板标题**：`AI 盘中解读 · 2026-04-15`

| Profile 标签 | Aggressive / Standard |
| 时间 | "2 分钟前" / "10:30" / "1 小时前" |
| 操作 | 点击切换回该对话；hover 显示"继续对话"提示 |

注意：

1. 最近对话列表只展示**强势筛选 AI 点评**会话，不与“问股”会话混合
2. 这是“围绕一次筛选任务的会话列表”，不是自由股票问答历史

#### 4.3.3 会话持久化

| 规则 | 说明 |
|------|------|
| 存储位置 | 本地 `localStorage` + 后端数据库（通过 agent chat session API） |
| 会话 key | `screener_{object_type}_{object_id}_{trade_date}_{profile}` |
| 保留策略 | 每个对象类型最多保留最近 10 个会话 |
| 过期策略 | 超过 7 天的会话自动清理 |
| 会话标题 | 自动生成，如 "石大胜华 AI 点评 · 2026-04-14" |

会话产品规则要额外明确：

1. 用户再次打开同一个点评对象时，默认先展示上次会话
2. 面板顶部必须提供 `基于最新数据重新分析` 按钮
3. 用户主动点击重新分析后，才发起新一轮 LLM 调用
4. 每轮回答都必须带有自己的“规则日期 / 行情时间 / profile / 总闸门”元信息，避免旧回答和新数据混淆

### 4.4 首条消息的回答合同与构造逻辑

用户点击按钮后，前端不弹输入框，而是**自动构造首条消息并发送**。首条消息由前端组装 prompt 后发送到后端 API。

但产品上更重要的不是“prompt 怎么拼”，而是**首条回答必须长成什么样**。

#### 4.4.0 所有回答都要遵守的四层结构

每次 AI 首条回答，必须显式区分下面四层：

1. **规则结论**
   规则引擎已经给出的结论，例如 `今日不做`、`主仓`、`买点不清晰`
2. **AI 解释**
   用自然语言解释为什么规则会得出这个结论
3. **外部补充**
   通过工具调用得到的实时行情、新闻、板块等背景信息
4. **可执行提醒**
   用户下一步该观察什么，而不是直接替用户下命令

如果 AI 回答里没有把这四层分开，用户就容易把 AI 当成第二个决策引擎。

#### 4.4.1 候选股点评 prompt 结构

```
system: 你是一个短线交易助手。请基于以下强势筛选数据，对这只股票做深度点评。
        你可以调用工具获取实时行情、新闻、板块数据来辅助判断。

user: 【基础信息】
      - 股票：石大胜华 (603026.SH)
      - 画像：Aggressive
      - 交易日：2026-04-14
      - 板块：电力设备
      - 地位：前排换手
      - 机会标签：一致再加速

      【评分总览】
      - 排序分：63.1 | 延续分：63.3 | 弹性分：86.2
      - 风险分：53.3 | 可买分：70.0
      - 建议区间：97.04 - 100.00

      【6 维拆解】
      - strength_confirmation: 30.0/30.0 (100%)
      - capital_support: 2.0/20.0 (10%)
      - buyability: 15.0/15.0 (100%)
      - volume_price_track: 9.0/15.0 (60%)
      - sector_resonance: 6.0/12.0 (50%)
      - trend_elasticity: 7.0/8.0 (88%)

      【当前策略状态】
      - 20 日窗口：失效（成功率 20.0%）
      - 60 日窗口：失效（成功率 18.3%）
      - 综合判定：今日不做

      请回答：
      1. 这只票为什么入选？核心优势是什么？
      2. 最大的风险点在哪里？
      3. 明天什么情况下可以考虑介入？什么情况下绝对不买？
      4. 在当前策略停用的背景下，这只票值得关注吗？

      要求：
      1. 先用 200-300 字给出首屏摘要
      2. 再按固定结构展开要点
      3. 不套话，不瞎猜，不和规则结论冲突
```

#### 4.4.2 二次决策 prompt 结构

输入：策略健康数据 + 默认组合 + 主线识别 + 落选说明

首条回答合同：

1. 今天做不做
2. 规则为什么这么定
3. 主仓 / 次仓 / 观察仓分别怎么看
4. 哪些信号才允许升级执行
5. 哪些情况直接劝退

#### 4.4.3 盘中信号 prompt 结构

输入：交易时段 + 置信度 + 各票实时价格 + 状态 + 与建议区间的关系

首条回答合同：

1. 当前时段最该关注什么
2. 主仓状态
3. 次仓状态
4. 观察仓状态
5. 接下来 30-60 分钟观察重点

注意：这类回答不能改写昨晚的固定顺序，也不能用 AI 结论覆盖规则风控标签。

#### 4.4.4 落选分析 prompt 结构

输入：落选股票列表 + 各自评分 + 淘汰原因标签

首条回答合同：

1. 最可惜落选 Top3
2. 每只票的主淘汰原因
3. 哪些只是“今天不合适”
4. 哪些是“本来就不该做”

### 4.5 追问机制

首条消息生成完成后，输入框激活，用户可以：

| 追问类型 | 示例 |
|----------|------|
| 对比分析 | "帮我对比它和利通电子，哪个更值得明天关注？" |
| 深入某维度 | "资金承接只有 10%，这种情况常见吗？" |
| 板块关联 | "电力设备板块还有其他好的吗？" |
| 情景推演 | "如果明天电力设备板块大跌，这只票会怎么样？" |
| 历史参考 | "这只票以前有类似走势吗？" |

LLM 在追问中可以继续调用工具获取数据，形成深度分析。

为了降低不会提问用户的门槛，面板底部应提供快捷追问 chips，例如：

1. `这只票最大风险是什么？`
2. `和主仓比谁更强？`
3. `什么情况下直接放弃？`
4. `如果主线转弱怎么办？`

## 5. 非功能需求

| 需求 | 说明 |
|------|------|
| **LLM 模型** | 复用项目现有的 LLM 配置（`LLMToolAdapter`），零额外配置 |
| **工具调用** | LLM 可以调用现有 agent 工具（行情、新闻、板块分析等） |
| **超时时间** | 120 秒（比问股略长，因为点评需要深度分析） |
| **温度参数** | 0.3（比问股低，点评不需要太发散） |
| **最大 token** | 1500（控制输出长度） |
| **流式输出** | SSE 流式输出，与问股页面一致 |
| **降级策略** | LLM 调用失败时，面板展示"AI 点评暂时不可用"，不影响规则引擎展示 |
| **移动端** | 移动端面板全屏弹出（与现有问股移动端体验一致） |
| **信任条必显** | 每次回答都必须带规则日期、profile、行情时间、已调用工具、规则总闸门 |
| **不展示详细内部推理** | 面板展示分析阶段和数据来源，不展示详细 chain-of-thought |
| **会话前台隔离** | 强势筛选 AI 会话只在强势筛选内展示，不与问股历史混合 |

- [ ] 关闭面板不中断 LLM 调用
- [ ] LLM 调用失败时展示降级提示

- [ ] 面板弹出动画流畅
- [ ] 骨架屏占位美观
