## 2. 文档目标

本清单用于把“强势筛选二次决策与执行辅助”继续往下推进一层，形成可执行的研发实施顺序，供前端、后端、接口、测试协同落地。

重点回答四件事：

- 新总闸门先落哪一层，后落哪一层
- 前后端各自要交付什么
- API / Schema 应在什么节点冻结
- 测试怎样跟着实施顺序介入，而不是最后补

## 3. 当前任务主线

本轮开发任务不再围绕旧的“策略健康”收敛，而统一围绕以下新口径推进：

- `20日进攻许可`
- `60日主线可信度`
- `市场环境`
- `机会质量`
- `市场环境 × 机会质量` 主矩阵
- `20日进攻许可` 动作封顶
- `系统停用 / 退出停用 / 恢复正常`
- `V1 官方入口固定 4% / 2亿 / 2%`
- `页面官方展示固定 Top30`
- `Standard 官方回测链路`
- `Aggressive 折叠式进攻补充观察层`

一句话：

**先把新总闸门做成独立、可解释、可测试的规则链，再把它接回二次决策页面。**

## 4. 总体实施原则

- 先做 `新总闸门后端规则链`，再做 `页面表达切换`
- 先冻结 `20日 / 60日 / 市场环境 / 机会质量 / 动作矩阵` 的字段结构，再推进前端整合
- 先把“今天能不能进攻”和“这套主线值不值得信”拆开，再清理旧的“策略健康”心智
- 先让页面能稳定展示 `双卡 + 主矩阵结果`，再做 `盘中低置信度 / 风险提示条 / 停用恢复`
- 先把官方入口、展示数量和回测画像收口到服务端，再清理前端可调控件
- `Aggressive` 只能作为补充观察层实现，不得重新进入官方组合或官方回测口径
- 测试不放到最后一次性补，而是跟随每个阶段同步进入
- 每个阶段都要允许“降级但可用”，避免追求一步到位导致整体不可交付

## 5. 推荐实施顺序

推荐整体顺序如下：

1. 后端新总闸门基础数据结构
2. 后端四个核心判定模块
3. 动作主矩阵与 `20日进攻许可` 封顶
4. 官方入口基线与 `Top30` 固化
5. API / Schema 冻结
6. 前端双卡与顶部摘要切换
7. `Aggressive` 折叠补充层
8. 官方回测 `Standard-only`
9. 风险提示条、停用 / 恢复页面表达
10. 盘中低置信度与收口联动
11. 测试联调、回归与验收

这是最小风险顺序。原因是：

- 如果没有稳定的后端总闸门结果，前端无法正确表达新心智
- 如果 API / Schema 不先定，前后端会反复改字段
- 如果继续沿用旧的“策略健康”字段驱动前端，后面会出现新旧规则并存

## 7. 后端实施顺序

### 7.1 第一阶段：新总闸门数据骨架

优先级：`P0`

任务：

1. 为二次决策结果新增统一 gate payload
2. 定义 `20日进攻许可` 卡结构
3. 定义 `60日主线可信度` 卡结构
4. 定义 `市场环境` 结构
5. 定义 `机会质量` 结构
6. 定义 `risk_banner` 结构

建议输出字段：

- `action_level`
- `action_level_reason`
- `market_environment`
- `opportunity_quality`
- `attack_permission_card`
- `theme_confidence_card`
- `risk_banner`
- `system_disable_state`

### 7.1.1 官方入口参数归一化

优先级：`P0`

任务：

1. 将 `MomentumScreenerService` 默认基线改为：
   - `min_change_pct = 4.0`
   - `min_amount = 2e8`
   - `min_turnover = 2.0`
   - `top_n = 30`
2. 更新 `MOMENTUM_ENTRY_BASELINE_VERSION`
3. API 层继续兼容旧请求字段，但生产链路必须归一化为官方基线
4. 候选池缓存 key 使用归一化后的官方基线，提高命中率
5. 保持 `main_board_only = false`，覆盖主板、创业板、科创板

验收：

- 只改旧客户端请求中的 `top_n` 或入口阈值，不应改变官方二次决策结果
- API 响应中的 `entry_baseline_version` 能反映新基线

### 7.2 第二阶段：20日进攻许可模块

优先级：`P0`

任务：

1. 接入最近 `20` 个交易日历史样本
2. 实现“买点先触发，再看利润窗口”的命中判断
3. 按角色门槛计算命中率
4. 产出 `可进攻 / 恢复中 / 暂停进攻`
5. 补充分数与解释文案

关键规则：

- 龙头核心：`>= 2.0%`
- 前排换手：`>= 2.5%`
- 观察备选：`>= 1.5%`
- `可进攻 >= 55%`
- `恢复中 >= 40%`
- `可进攻` 至少 `5` 个有效样本
- `恢复中` 至少 `3` 个有效样本

### 7.3 第三阶段：60日主线可信度模块

优先级：`P0`

任务：

1. 接入最近 `60` 个交易日主线验证样本
2. 实现第一主线命中判断
3. 实现最强核心 / `Top3` / `Top5` 的分层记分
4. 产出 `可信 / 恢复中 / 存疑`
5. 输出解释文案

关键规则：

- 最强核心命中第一主线：`0.6`
- 第一主线覆盖次日强票 `Top3 >= 2`：`0.4`
- 第一主线覆盖次日强票 `Top5 >= 3`：`+0.1`
- 单日封顶 `1.0`
- `可信 >= 0.60`
- `恢复中 >= 0.45`
- `可信` 至少 `12` 个有效样本
- `恢复中` 至少 `8` 个有效样本

### 7.4 第四阶段：市场环境模块

优先级：`P0`

任务：

1. 实现双层样本池：
   - `昨日二次决策 Top3`
   - `昨日候选池 Top10`
2. 实现核心溢价判断
3. 实现广度达标判断
4. 输出 `强 / 中等 / 弱`

关键规则：

- 昨日 `Top3` 至少 `1` 只：
  - 今日先满足买点触发
  - 且 `T+1/T+2 利润窗口 >= 2.0%`
- 昨日 `Top10`：
  - 命中率 `>= 30%`
  - 平均利润窗口 `>= 2.0%`
- `强 = 核心有溢价 + 广度达标`
- `中等 = 只好一边`
- `弱 = 两边都不行`

### 7.5 第五阶段：机会质量模块

优先级：`P0`

任务：

1. 统计默认组合中“买点清晰 / 可执行”的数量
2. 计算主仓盈亏比
3. 计算主线集中度
4. 按边界规则输出 `强 / 中上 / 中 / 弱`

关键规则：

- `3只清晰 = 强`
- `2只清晰 = 中上`
- `1只清晰 = 中`
- `0只清晰 = 弱`
- 主仓盈亏比门槛：
  - `预期利润空间 >= 预期失效空间的 1.5 倍`
- 主线集中度：
  - 默认组合至少 `2` 只来自第一主线

### 7.6 第六阶段：动作主矩阵与封顶

优先级：`P0`

任务：

1. 实现 `市场环境 × 机会质量` 主矩阵
2. 再实现 `20日进攻许可` 封顶
3. 统一输出最终 `action_level`
4. 输出 `matrix_reason` 与 `cap_reason`

关键规则：

- 主矩阵先算：
  - `强 × 强 = 强烈可做`
  - `强 × 中上 = 可正常出手`
  - `强 × 中 = 谨慎出手`
  - `强 × 弱 = 仅观察`
  - `中等 × 强 = 可正常出手`
  - `中等 × 中上 = 谨慎出手`
  - `中等 × 中 = 仅观察`
  - `中等 × 弱 = 今日不做`
  - `弱 × 强 = 谨慎出手`
  - `弱 × 中上 = 仅观察`
  - `弱 × 中 = 今日不做`
  - `弱 × 弱 = 今日不做`
- 再封顶：
  - `可进攻`：不压级
  - `恢复中`：最高 `可正常出手`
  - `暂停进攻`：强环境 + 强机会时最高 `谨慎出手`，否则按 `仅观察 / 今日不做` 收口

### 7.7 第七阶段：停用 / 恢复

优先级：`P1`

任务：

1. 实现连续 `5` 个交易日双弱的停用判断
2. 实现退出停用条件
3. 实现恢复正常条件
4. 输出停用原因与恢复阶段

关键规则：

- `系统停用`
  - 连续 `5` 个交易日
  - `20日进攻许可 = 暂停进攻`
  - 且 `60日主线可信度 = 存疑`
- 退出停用：
  - `20日进攻许可` 回到 `恢复中`
  - 且 `市场环境 != 弱`
- 退出停用后：
  - 只恢复到 `仅观察 / 最多谨慎出手`

### 7.8 第八阶段：盘中低置信度联动

优先级：`P1`

任务：

1. 保留现有低置信度模块
2. 让盘中低置信度与新总闸门输出共存
3. 增加 `risk_banner` 类型输出
4. 确保盘中收口结果不突破总闸门边界

## 11. 推荐实际推进顺序

## 12. 交付完成定义

当以下条件同时满足，才视为这一轮任务真正完成：

- 页面用户侧彻底移除“策略健康”
- 页面能稳定展示：
  - `今日出手级别`
  - `20日进攻许可`
  - `60日主线可信度`
- `今日出手级别` 已按 `市场环境 × 机会质量` 主矩阵输出
- `20日进攻许可` 已正确封顶
- `60日主线可信度` 已只做提示，不再硬压动作
- `系统停用 / 退出停用 / 恢复正常` 已形成完整闭环
- 官方入口固定为 `4 / 2亿 / 2%`
- 页面展示固定为 `Top30`
- 官方回测只创建 `Standard` 链路 run
- `Aggressive` 只作为折叠补充观察层，不进入官方组合或官方胜率
- 测试覆盖新总闸门的关键边界
