# 主仓排序 P0 诊断

生成时间：2026-04-21  
数据来源：测试环境真实回测 `momentum_bt_3ce6f7b28b4a4160`  
分析区间：`2026-01-15` 至 `2026-04-17`，共 `60` 个交易日  
聚焦问题：`main_slot_underperformed`

## 1. 这份诊断回答什么问题

60 日真实回测已经证明，当前最大问题不是候选池捞不到强票，而是主仓经常没有排到“后续最值得优先做的那只”。

这份文档只聚焦一个问题：

- 当前主仓到底是怎么被选出来的
- 为什么它会系统性压掉后面真正更强的票
- 接下来 P0 应该优先改哪几条规则

## 2. 当前主仓收口逻辑

当前主仓不是直接按原始 `rank_score` 选，而是至少经过两轮再加工。

### 2.1 第一轮：先构造 `_decision_score`

代码位置：

- [momentum_secondary_decision_service.py](/D:/AI_Project/_remote_edit/daily_stock_analysis/src/services/momentum_secondary_decision_service.py:654)

当前公式：

```python
decision_score = (
    rank_score * 0.55
    + continuation_score * 0.20
    + buyability_or_extension * 0.15
    + ROLE_PRIORITY[role_key]
    + BUY_POINT_PRIORITY[buy_point_status]
    - risk_score * 0.10
)
```

这一步已经不再是“原始强度排序”，而是把：

- 角色权重
- 买点状态
- 风险惩罚

一起提前混进了排序。

### 2.2 第二轮：再构造 `_portfolio_priority`

代码位置：

- [momentum_secondary_decision_service.py](/D:/AI_Project/_remote_edit/daily_stock_analysis/src/services/momentum_secondary_decision_service.py:3329)

当前公式：

```python
portfolio_priority = (
    _decision_score
    + theme_score * 0.18
    + ROLE_PRIORITY[role_key]
    + BUY_POINT_PRIORITY[buy_point_status]
    - risk_score * 0.08
)
```

注意这里的：

- `ROLE_PRIORITY`
- `BUY_POINT_PRIORITY`
- `risk_score`

被重复加权了一次。

也就是说，角色和买点不是“解释层”，而是已经成为主仓排序的强干预项。

### 2.3 第三轮：主仓有一个硬优先级

代码位置：

- [momentum_secondary_decision_service.py](/D:/AI_Project/_remote_edit/daily_stock_analysis/src/services/momentum_secondary_decision_service.py:3338)

当前逻辑：

```python
clear_candidates = [item for item in candidates if item["_buy_point_status"] == "clear"]
pool = clear_candidates or candidates
return max(pool, key=lambda item: self._portfolio_priority(item, theme_score_map))
```

含义非常直接：

- 只要市场里存在 `clear` 候选，主仓就只在 `clear` 池里选
- 那些还处于 `waiting`，但后续爆发力更强的票，会先天处于劣势

## 3. 60 日回测里的主仓错排事实

### 3.1 错排不是偶发，而是结构性问题

本轮回测中：

- `main_slot_underperformed` 共出现 `51` 次
- 也就是 60 个交易日里，有 `51` 天候选池中存在明显优于主仓的标的
- 平均利润窗口差值达到 `11.3822%`

### 3.2 更优标的大多根本没进官方组合

51 个错排日里：

- 更优标的 `not_selected`：`43` 天
- 更优标的被选进默认组合：`8` 天

这 8 天里：

- 作为 `secondary`：`6` 天
- 作为 `watch`：`2` 天

结论：

- 问题不只是“主仓和次仓调换错了”
- 更多时候，是更优标的直接被挡在官方组合之外

### 3.3 主仓几乎被“龙头核心 + 清晰买点”垄断

51 个错排日中：

- 主仓角色 `leader`：`51 / 51`
- 更优标的角色：
  - `leader`：`33`
  - `front`：`10`
  - `mid`：`8`

买点状态组合：

- `main:clear | best:waiting`：`25`
- `main:clear | best:clear`：`24`
- `main:waiting | best:waiting`：`2`

这说明当前主仓排序强烈偏向：

- 龙头核心
- 已经 `clear`
- 风险更低

而不是单纯偏向“后续两天最有延续性的那只”。

### 3.4 更优标的大多原始排名并不高

51 个错排日里：

- 更优标的原始排名更靠后：`47`
- 更优标的原始排名更靠前：`4`

这件事很关键。

它说明问题不是“系统把 Top1 明显错排成了 Top8”，而是：

- 当前系统对“后排但更有爆发力的真强票”识别能力不足
- 它更偏好“当前更像主仓模板”的票，而不是“未来两天更强”的票

## 6. 当前 P0 结论

### 6.1 当前主仓模型的真实偏向

当前主仓模型实际偏向：

- 低风险
- 龙头角色
- 已经 `clear`
- 所属主题得分更高
- 原始排名更靠前

但它缺少的能力是：

- 从后排候选中识别“未来两天更容易走成最强”的票
- 允许“高弹性但暂未完全 clear”的票挑战主仓
- 在同主题内部把“更有爆发性的进攻票”提到更靠前位置

### 6.2 当前模型最本质的问题

最本质的问题不是“权重差一点”，而是排序哲学本身偏了。

当前主仓在做的是：

- 选一只最像“安全主仓模板”的票

而用户真正需要的是：

- 选一只明天最值得优先盯、最可能打出空间、最值得先找买点的票

这两件事不是同一个目标。

## 7. P0 改造建议

### 7.1 去掉“`clear_candidates` 先手硬筛”

当前主仓先只在 `clear` 池里选，这个门槛太硬。

建议改成：

- `clear` 只做加分项，不做硬门槛
- 允许 `waiting` 候选在强度明显更高时挑战主仓

### 7.2 角色与买点状态降权，改成 tie-breaker

当前 `leader + clear` 组合对排序的影响过强，而且被重复加权。

建议改成：

- 原始强度分做主排序
- 角色、买点、主题只作为小幅修正
- 不能让解释因子推翻真正的强度排序

### 7.3 增加“爆发潜力挑战主仓”机制

对于原始排名 Top10 内的候选：

- 如果 `continuation_score`、`extension_score` 明显高于主仓
- 且真实风险并未极端失控
- 即使当前只是 `waiting`

也应该允许它挑战主仓或至少升为次仓，而不是直接留在组合外。

### 7.4 增加“已入组合但比主仓更强”的自动晋升规则

现在有 8 天更优标的其实已经在官方组合里，但被放在 `secondary / watch`。

建议加一条简单规则：

- 若某个次仓或观察仓相对主仓的原始强度和延续性明显领先
- 不允许仅因“主仓模板更标准”而压着不升

### 7.5 把 P0 目标改成“主仓 alpha”，而不是“主仓解释性”

后续回测应新增一个更直接的 P0 验证指标：

- 主仓相对候选池 Top10 最优标的的利润窗口差值

当前均值是：

- `11.3822%`

P0 的目标应该是先把这个差值显著收窄，而不是先追求“主仓理由看起来更顺”。

## 8. 影子排序实验

为了确认问题是否能通过“简单调权重”解决，本轮额外对 51 个 `main_slot_underperformed` 样本做了 4 组离线影子排序实验。

实验只在候选池 Top10 内重排，不改生产代码，也不影响线上结果。

| 影子方案 | 命中事后最优 | 平均被选 T+2 利润窗口 | 相对事后最优平均差距 |
| --- | ---: | ---: | ---: |
| 仅去掉 `clear` 硬门槛，保留当前优先级 | `3 / 51`，`5.88%` | `5.8160%` | `10.5585%` |
| 去掉重复角色/买点加权，并去掉 `clear` 硬门槛 | `4 / 51`，`7.84%` | `6.1827%` | `10.1918%` |
| 让原始排名与延续性占主导，并去掉 `clear` 硬门槛 | `3 / 51`，`5.88%` | `5.9540%` | `10.4205%` |
| 增强进攻弹性偏置，并去掉 `clear` 硬门槛 | `3 / 51`，`5.88%` | `6.5641%` | `9.8104%` |

### 8.1 影子实验结论

结果说明：

- 只取消 `clear` 硬门槛，不足以修复主仓错排
- 只把重复的角色/买点权重降下来，也只能小幅改善
- 增强进攻弹性后，平均利润窗口有所改善，但命中事后最优仍然很低
- 当前输入特征本身没有充分表达“未来 1-2 天谁更可能继续打出空间”

因此，P0 不应该只做一次静态权重调整。

更合理的方向是：

- 保留现有规则作为可解释底座
- 增加一层由历史回测校准出来的 `forward_alpha_score`
- 用它专门回答“这只票在当前结构下，未来 1-2 天继续走强的经验概率和盈亏比怎么样”

一句话总结：

简单调权重只能让规则看起来更合理，但不能让系统真正学会“哪些形态后续更容易兑现”。

## 9. 下一步建议

如果按开发顺序推进，P0 下一步最合理的是：

1. 先把当前主仓排序拆成“主排序分”和“解释修正分”两层
2. 补一份候选股级别的回测训练/诊断数据集，每一行对应一个候选股在某个交易日的规则特征和 T+1/T+2 结果
3. 在现有规则分之外增加 `forward_alpha_score`，先用历史分桶/经验校准实现，不直接上黑盒模型
4. 跑一轮 60 日离线对比，重点看 51 个错排日里，有多少天能把更优票抬进主仓或至少抬进前二
5. 只有主仓 alpha 明显改善后，再继续调总闸门和买点执行层

一句话收口：

当前主仓不是“不会选票”，而是“太执着于选一只看起来最稳、最像主仓模板的票”，结果把真正更强的票经常压在了后面。

## 10. P0 开发拆解

### 10.1 先沉淀候选股级别诊断数据

需要在回测结果中补充一层 candidate-level 明细，每一行代表“某个交易日的一只候选股”。

建议至少包含：

- `trade_date`
- `ts_code`
- `name`
- `raw_rank`
- `rank_score`
- `role_key`
- `buy_point_status`
- `continuation_score`
- `extension_score`
- `risk_score`
- `theme_score`
- `current_decision_score`
- `current_portfolio_priority`
- `selected_slot`
- `t1_profit_window`
- `t2_profit_window`
- `t2_max_drawdown`
- `is_hindsight_best_top10`
- `is_selected`

这一步的目标不是直接改推荐结果，而是先把“为什么当前规则错过它”变成可统计、可复盘的数据。

### 10.2 新增 `forward_alpha_score`

`forward_alpha_score` 的职责只回答一个问题：

- 在历史相似结构中，这只票未来 1-2 个交易日继续打出利润窗口的经验概率与盈亏比如何

第一版不建议直接上黑盒模型，建议先做经验分桶：

- 按 `role_key` 分桶
- 按 `buy_point_status` 分桶
- 按 `raw_rank` 分桶
- 按 `continuation_score` 分桶
- 按 `extension_score` 分桶
- 按 `risk_score` 分桶
- 按市场环境强弱分桶

每个分桶产出：

- 历史样本数
- T+2 正收益率
- T+2 平均利润窗口
- T+2 平均最大回撤
- 盈亏比修正分
- 样本不足时的降权系数

### 10.3 接入排序时只做“校准层”，不要替代规则层

推荐排序应拆成两层：

- 规则底座分：保留当前 `rank_score / continuation / buyability / role / buy_point / risk / theme`
- 前瞻校准分：新增 `forward_alpha_score`

第一版接入建议：

- `forward_alpha_score` 不直接一票否决
- 但允许它把 Top10 内高弹性票从观察或未入选抬到次仓/主仓
- 对样本数不足的分桶，只允许小幅加减分
- 对样本数充足且历史表现稳定的分桶，允许更大幅度修正

### 10.4 验证指标

上线前至少跑同一段 60 交易日对比：

- `main_slot_underperformed` 次数是否下降
- 主仓相对候选池 Top10 最优标的的平均利润窗口差距是否下降
- 官方 Top3 是否重新跑赢原始排序 Top3
- 官方 Top3 的 T+2 正收益率是否提升
- 官方 Top3 的 T+2 最大回撤是否没有明显恶化
- 强烈可做 / 可正常出手日是否没有被错误压成观察

如果只提升收益窗口、但最大回撤显著恶化，这一版不能直接上线为默认逻辑，只能先作为影子评分展示。

### 10.5 推荐落地顺序

1. 先开发 candidate-level 回测明细导出
2. 再开发分桶统计与 `forward_alpha_score`
3. 先影子接入，只展示新分数和新排序，不改变线上推荐
4. 跑 60 日对比，确认主仓 alpha 明显改善
5. 再把新排序切入主仓/次仓/观察仓生产逻辑

## 11. 2026-04-21 首轮校准落地

本轮已先完成主链路的最小生产校准：

- 主仓不再只从 `clear` 买点池中选择，`waiting` 票可以凭更强前瞻分挑战主仓
- `ROLE_PRIORITY` 与 `BUY_POINT_PRIORITY` 不再在组合排序中重复加权，角色与买点改为轻量解释修正
- 新增 `forward_alpha_score`，用透明规则先验刻画 T+1/T+2 延续潜力
- `extension_score` 不再被视为越高越好，而是先转换成 `extension_signal_score`：适度高弹性更有利，极端高弹性只保留进攻属性，不再无脑放大排序权重
- 次仓跨主题分配新增优先级差距保护：只有跨主题候选与最强剩余候选足够接近时，才允许为了组合分散去牺牲主线内更强票
- 二次决策接口新增 `candidate_diagnostics`，记录每只候选的规则底座分、解释修正分、前瞻分、最终优先级与入选槽位
- 回测单日详情的 `candidate_top10` 会带出 `decision_diagnostics`，用于复盘“更强票为什么没进主仓/次仓”

受本地缺少真实数据源 Token 限制，本轮无法直接复跑完整 60 交易日。先用旧报告中保留的 6 个重点日详情做离线复盘小样本：

- 旧组合主仓平均 T+2 利润窗口：`3.09%`
- 新组合主仓平均 T+2 利润窗口：`4.72%`
- 旧组合 Top3 平均 T+2 利润窗口：`5.59%`
- 新组合 Top3 平均 T+2 利润窗口：`6.14%`

这只能证明首轮方向值得进入测试环境复跑，不能替代完整 60 日真实回测结论。

这仍然不是最终的历史分桶校准层。下一轮应基于新的 candidate-level 诊断数据继续沉淀样本，再把 `forward_alpha_score` 从规则先验升级为历史回测分桶校准。
