# 明日观察池摘要 MVP 需求文档

## 1. 文档信息

- 功能名称：明日观察池摘要
- 所属模块：`Momentum Screener / 强势筛选`
- 文档类型：MVP 需求文档
- 当前状态：`draft for assignment`
- 目标版本：`MVP`

## 2. 当前最需要解决的痛点

强势筛选页已经可以输出 TopN 结果，但用户在收盘后仍然要自己做第二次整理：

- 从表格里手动挑出明天优先关注的 2 到 3 只股票
- 再自己总结当前集中在哪个题材
- 再自己补一句“风险提醒”和“明日执行建议”

这一步虽然不复杂，但每天都重复，既耗时，也容易因为手工整理而漏看重点。  
因此，当前最值得优先解决的痛点不是“再提升筛选算法复杂度”，而是“把已有结果自动整理成可执行的明日观察池”。

## 3. 为什么这是最合适的 MVP 单元

这个需求符合最小 MVP 原则：

- 只解决一个明确痛点：减少人工整理观察池
- 完全复用现有筛选结果，不改筛选接口
- 不引入新配置、新数据源、新后端任务
- 用户一眼能感知价值，适合演示和截图

也就是说，它不是“再做一个新产品”，而是在现有结果之上补一层最小可用的决策摘要。

## 4. MVP 目标

在用户完成一次强势筛选后，页面自动生成一块“明日观察池摘要”，帮助用户快速得到：

- 明日优先关注的 Top3 标的
- 当前结果里更偏进攻或更偏低风险的代表标的
- 当前结果的题材聚焦方向
- 需要重点注意的风险标签
- 一段可直接复制分享的观察池摘要文本

## 5. 目标用户

- 每日收盘后会做次日备选池的短线用户
- 想快速把筛选结果同步到群聊、笔记或飞书文档的用户
- 已经认可当前筛选结果，但不想重复做人工整理的用户

## 6. 功能范围

### 6.1 本次 MVP 要做

- 在强势筛选页新增“明日观察池摘要”区块
- 根据当前排序结果自动提取 Top3 观察标的
- 自动识别题材聚焦信息
- 自动给出“进攻首选”或“低风险优先”提示
- 自动汇总当前结果中的风险提醒
- 支持一键复制观察池摘要文本

### 6.2 本次 MVP 不做

- 不改后端筛选接口
- 不调用额外 LLM 生成二次总结
- 不新增“保存到自选股”或“同步到回测”功能
- 不支持用户自定义摘要模板
- 不处理盘中动态刷新

## 7. 用户故事

### 场景 1：收盘后快速形成次日观察池

作为一个收盘后复盘的用户，  
当我执行完强势筛选后，  
我希望系统直接告诉我“明天先看谁、题材在哪、风险是什么”，  
这样我不需要再从表格中手动摘抄整理。

### 场景 2：把结果发到群里或笔记里

作为一个会把复盘结果同步到飞书或聊天群的用户，  
当我看到观察池摘要后，  
我希望可以一键复制，  
这样我能直接粘贴出去，而不是手写总结。

## 8. 交互方案

### 8.1 区块位置

- 位于强势筛选页摘要卡区下方、结果表格上方

### 8.2 展示内容

- 标题：`明日观察池摘要`
- Top3 观察标的卡片
- 进攻首选或低风险优先卡片
- 题材聚焦标签
- 风险提醒
- 执行建议

### 8.3 操作按钮

- `复制观察池摘要`

## 9. 验收标准

- 未执行筛选时，摘要区显示空状态，复制按钮禁用
- 执行筛选后，摘要区可以基于现有结果自动渲染
- 标准画像下可以展示低风险优先提示
- 激进画像下可以展示进攻首选提示
- 点击复制按钮后，可以得到结构化文本摘要
- 切换排序方式后，摘要内容跟随当前排序结果更新

## 10. 成功标准

- 用户可以在 10 秒内看懂“明日先看谁”
- 用户不需要手工二次整理即可完成一次观察池输出
- 支持直接截图或复制，适合作为演示和作业提交材料

## 11. 技术实现约束

- 前端本地计算完成摘要生成
- 数据来源仅使用现有 `MomentumScreenerResponse`
- 不新增 API 字段
- 不新增配置项

## 12. 风险与回滚

### 风险点

- 摘要属于规则压缩，不代表完整交易建议
- 如果排序结果本身较分散，题材聚焦信息会偏弱
- 风险提醒基于已有标签，不额外引入新的风险模型

### 回滚方式

- 删除前端摘要区块和对应复制逻辑
- 不影响现有筛选、排序、导出、明细抽屉等核心能力

## 13. V1.3 Decision Intelligence Contract

第四阶段起，强势筛选摘要与 AI 点评不再定位为“行情记者”或“结果描述器”，而是定位为 `Logic Auditor`（短线交易逻辑审计员）。它的目标不是替规则层重新选股，而是把规则层已经给出的 Official Top3、Risk Stack、Mainline Intensity 和总闸门结论翻译成可复盘、可执行、可质疑的决策情报。

### 13.1 AI 目标

- 先解释 `Core Logic`：为什么该标的能成为主线/强度候选，重点引用主线共振、角色、官方分和 Mainline Intensity。
- 再执行 `Risk Audit`：逐只指出 Risk Stack 触发项，并额外扮演 Devil's Advocate，至少找出一个背离、瑕疵或未确认项。
- 最后给出 `Execution Guard`：把 V1.3 可交易合同前置到 T 日晚间说明中，尤其是 `T+1 Open >= T0 Close * 0.99`，若失败则只能放弃或仅观察。

### 13.2 输入上下文

AI 摘要必须优先使用后端结构化上下文，不允许只凭自然语言描述发挥：

- `risk_stack / risk_stack_count / risk_stack_veto`：说明高位、封板、背离、无主线等风险是否叠加。
- `mainline_intensity_count / mainline_intensity_multiplier / mainline_intensity_bonus`：说明板块/题材共振如何影响官方排序。
- `adaptive_gate`：说明是否因最近总闸门防守成功率过高而进入弱市动态收口。
- `execution_guard`：说明 T+1 不深低开、收阳与 T+2 利润缓冲的执行边界。

### 13.3 验收标准

- AI 输出必须包含 `[Core Logic]`、`[Risk Audit]`、`[Execution Guard]` 三个核心段落。
- 默认 Top3 的每只股票都必须出现至少一个风险审计点；没有硬风险时，也要说明最接近的未确认项。
- AI 不得把 `今日不做`、`仅观察`、`Risk Stack Veto` 或动态主线阈值不足改写成可执行推荐。
