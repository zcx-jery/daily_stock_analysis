# 首页个股分析 Tushare 6000 积分增强产品文档

## 1. 文档信息

- 文档类型：产品方案
- 当前状态：Draft
- 最近更新：2026-05-04
- 关联 SPEC：[首页个股分析 Tushare 6000 积分增强 SPEC](home-stock-analysis-tushare-enhancement-spec.md)
- 适用范围：首页个股分析的 A 股单票分析链路

## 2. 背景

当前首页个股分析已经可以完成选股输入、异步分析、报告摘要、Markdown 报告和详情字段展示。后端分析链路也已经具备基础面、筹码、所属板块、板块排名和报告详情提取的入口，因此 Tushare 6000 积分的第一阶段价值不是重做首页，而是增强报告生成前的结构化上下文，让 LLM 的判断更有数据支撑，并把可追踪快照保留下来。

Tushare 6000 积分对首页个股分析的主要增强点有四类：

- 基本面更稳：补齐估值、盈利能力、成长性、股息率、财报摘要和业绩事件。
- 资金流更强：补齐个股主力净流入、大小单结构和多日资金趋势。
- 板块联动更准：用同花顺行业和概念成分增强所属板块、领先板块和落后板块判断。
- 筹码结构更好：补齐胜率、成本分位、加权平均成本和筹码集中度，用于解释压力位、支撑位和追涨风险。

## 3. 产品目标

1. 首页分析不增加用户操作成本，仍保持“输入股票 -> 点击分析 -> 读报告”的主流程。
2. 报告中的趋势预测、操作建议和风险提示必须能引用更明确的数据证据。
3. 数据增强以 A 股为第一优先级，港股、美股继续走现有数据源和降级路径。
4. 单个 Tushare 接口失败不阻断整次分析，报告需要说明数据缺口和使用的数据源。
5. 第一阶段尽量不重构前端页面，优先增强 LLM 上下文、追踪快照和详情字段。

## 4. 用户价值

| 当前体验 | 增强后体验 |
| --- | --- |
| 报告能给出技术面和新闻驱动判断，但基本面证据不稳定。 | 报告能补充 PE/PB/股息率、ROE、毛利率、净利率、现金流和财报摘要，判断更像完整投研备忘。 |
| 资金判断主要依赖已有行情、新闻和部分 fallback 数据。 | 能看到 THS/DC 资金流的主力净流入、大单/中单/小单结构和 5 日资金趋势。 |
| 板块信息已经有入口，但成分和排名稳定性依赖现有数据源。 | 能用 `ths_index` 和 `ths_member` 识别同花顺概念、行业和成分关系，提升板块联动解释。 |
| 筹码分析有入口，但稳定性受数据源影响。 | 能用 `cyq_perf` / `cyq_chips` 解释当前价格相对成本分位、胜率和筹码集中区。 |
| 详情页已有部分字段，但用户不一定知道数据是否完整。 | 增加数据来源、数据日期、降级原因和可用性提示，提升透明度。 |

## 5. 首页信息架构

第一阶段不新增复杂入口，首页仍保持当前结构：

1. 股票输入区：保持现有股票搜索和分析按钮。
2. 报告摘要区：继续展示目标价、置信度、评级、风险和关键观点。
3. 报告正文区：Markdown 报告里增加基本面、资金流、板块联动、筹码结构证据。
4. 详情数据区：复用已经暴露的 `financial_report`、`dividend_metrics`、`belong_boards`、`sector_rankings`，后续再追加资金流和筹码结构卡片。
5. 数据质量区：在报告或详情中展示数据日期、来源、覆盖状态和降级原因。

## 6. 报告内容增强

### 6.1 基本面

面向中线判断和估值解释，报告应补充：

- 估值：`pe`、`pe_ttm`、`pb`、`ps_ttm`、`dv_ttm`、总市值、流通市值。
- 盈利能力：`roe`、`grossprofit_margin`、`netprofit_margin`、`roa`、`roic`。
- 成长性：营收同比、净利润同比、扣非净利润、EPS、经营现金流。
- 分红：每股分红、股息率、最近分红年度和派息稳定性。
- 财报事件：业绩预告、业绩快报、最新报告期和公告日期。

产品口径：

- 短线报告不把基本面作为买卖唯一依据，只作为估值压力、业绩兑现和风险底色。
- 中线报告需要把基本面纳入评级和目标价解释。
- 财报数据滞后时，必须标注报告期，避免用旧财报解释最新股价。

### 6.2 资金流

面向盘后复盘和短线建议，报告应补充：

- 当日主力净流入和净流入比例。
- 超大单、大单、中单、小单净流入结构。
- 近 5 日主力净额或多日资金方向。
- THS 与 DC 数据冲突时的差异说明。

产品口径：

- 主力净流入支持“趋势延续”和“回踩承接”的判断。
- 大单流出、小单流入支持“高位派发”或“短线拥挤”的风险提示。
- 资金流只作为短线确认信号，不直接覆盖风险控制。

### 6.3 板块联动

面向题材和行业共振判断，报告应补充：

- 个股所属同花顺概念、行业、主题和特色指数。
- 所属板块当日或近期表现排名。
- 个股相对所属板块的领先/落后状态。
- 同板块成分股强弱对比。

产品口径：

- 个股强于板块且资金流确认时，可解释为相对强势。
- 个股弱于强板块时，报告要提示“板块带动但个股承接不足”。
- 个股强但所属板块弱时，报告要提示“孤立上涨，持续性需二次确认”。

### 6.4 筹码结构

面向压力、支撑和追涨风险，报告应补充：

- `winner_rate`：当前价格对应获利盘比例。
- `weight_avg`：加权平均成本。
- `cost_5pct` / `cost_50pct` / `cost_95pct`：成本分位。
- `cyq_chips`：主要筹码密集区和上方套牢区。

产品口径：

- 价格低于或接近加权成本时，重点解释支撑和止损位置。
- 价格远高于 95% 成本分位且资金流走弱时，重点提示追涨风险。
- 筹码集中度提升且价格突破关键成本区，可作为趋势确认辅助。

## 7. 分阶段路线

### Phase 1：后端上下文增强

目标：少改前端，优先提升报告质量和数据追踪能力。

范围：

- 在现有 `get_fundamental_context`、`get_chip_distribution`、板块和资金流入口中增加 Tushare 增强数据。
- 把增强后的结构化数据注入 LLM prompt。
- 保存增强数据到 context snapshot，便于报告详情和排障。
- 继续复用现有 `financial_report`、`dividend_metrics`、`belong_boards`、`sector_rankings` 详情字段。

验收：

- 未配置 Tushare token 时，首页分析仍能按现有路径完成。
- 配置 6000 积分 token 后，A 股报告能在正文或详情中体现基本面、资金流、板块和筹码证据。
- 任一增强接口失败时，报告仍生成，并记录失败原因。

### Phase 2：报告详情轻量展示

目标：让用户能看到关键增强数据，不只藏在正文里。

范围：

- 新增“数据质量”提示，展示来源、数据日期和降级状态。
- 基本面详情补充估值、盈利能力和分红摘要。
- 板块详情补充同花顺板块关系和领先/落后解释。
- 资金流和筹码结构可先作为折叠详情，不改首页主视觉。

验收：

- 详情字段为空时不展示空卡片。
- 数据日期和报告生成时间区分清楚。
- 前端旧报告兼容，不因缺少新字段报错。

### Phase 3：策略解释增强

目标：让趋势预测和操作建议更稳定。

范围：

- 把资金流、板块联动、筹码结构纳入评分或 prompt 规则。
- 输出短线、中线两套不同证据权重。
- 形成“结论 -> 证据 -> 风险 -> 操作边界”的固定报告段落。

验收：

- 操作建议中必须包含至少一个价格或条件边界。
- 资金流和筹码信号冲突时，报告必须解释冲突。
- 基本面差但短线强势时，报告不能把短线结论包装成中线投资建议。

## 8. 数据能力映射

| 增强方向 | Tushare 接口 | 6000 积分可用性假设 | 首页价值 |
| --- | --- | --- | --- |
| 每日估值和股息率 | `daily_basic` | 官方文档显示至少 2000 积分可调，6000 覆盖 | 增强估值、股息率和市值解释 |
| 财务指标 | `fina_indicator` | 官方文档显示至少 2000 积分可调，6000 覆盖 | 增强 ROE、毛利率、净利率、现金流和成长性 |
| 业绩和分红 | `forecast`、`express`、`dividend` | 以 token 实际权限为准 | 增强财报摘要、业绩事件和分红说明 |
| THS 资金流 | `moneyflow_ths` | 官方文档显示 6000 积分可调 | 增强盘后资金确认和短线建议 |
| DC 资金流 | `moneyflow_dc` | 官方文档显示至少 5000 积分可调，6000 覆盖 | 提供另一套资金流校验 |
| 同花顺板块 | `ths_index`、`ths_member` | 官方文档显示 6000 积分可调 | 增强所属板块、成分关系和联动解释 |
| 筹码和胜率 | `cyq_perf`、`cyq_chips` | 官方接口文档显示 5000 积分级别可调，6000 覆盖；更高积分有更高频次/总量 | 增强压力位、支撑位和追涨风险解释 |

## 9. 降级和透明度

报告需要按以下顺序展示数据状态：

1. 完整增强：Tushare 数据正常，字段和日期完整。
2. 部分增强：部分接口成功，部分接口降级，报告说明缺口。
3. 基础模式：Tushare token 缺失、积分不足或接口异常，使用现有 AkShare / 其他 fallback。
4. 数据不可用：关键数据源均失败，只输出已知行情和新闻判断，并降低置信度。

建议在后续 UI 中补充以下状态：

- 数据源：`Tushare`、`AkShare`、`fallback`。
- 数据日期：交易日、报告期、公告日期分别展示。
- 覆盖状态：`complete`、`partial`、`fallback`、`missing`。
- 降级原因：权限不足、接口超时、字段为空、非 A 股市场、不在更新时间窗口。

## 10. 成功指标

- 报告证据完整率：A 股首页报告中至少 80% 能包含基本面、资金流、板块、筹码四类中的三类证据。
- 降级可解释率：增强接口失败时，报告详情或日志能定位到具体接口和原因。
- 前端兼容率：旧报告和非 A 股报告不出现空白卡片或运行错误。
- 用户可读性：趋势预测和操作建议中能明确写出数据依据和触发条件。

## 11. 边界和风险

- 6000 积分不覆盖所有独立权限接口，尤其分钟、港美股部分数据、公告和新闻类接口仍可能需要单独开通。
- 财务数据存在公告滞后，不能直接等同于当前交易日基本面变化。
- 资金流数据多为盘后更新，盘中实时分析需要明确数据时效。
- 同花顺数据版权有使用边界，商业化场景需要额外确认。
- LLM 需要被约束为“基于数据证据解释”，不能因为新增字段而给出确定性收益承诺。
