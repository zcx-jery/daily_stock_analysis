## 2. 文档目标

这份清单解决的是：

- 现有强势筛选从 beta 规则推进到 V1 产品规则，具体要改哪些点
- 后端、接口、前端、测试的实施顺序是什么
- 哪些是 P0 必做，哪些可以延后

一句话总结：

**这份清单不是重新设计产品，而是把已定下来的 V1 规则拆成可以执行的改造顺序。**

## 3. V1 改造总目标

V1 要实现的不是“小修小补”，而是把当前强势筛选从“半实验型 beta”改造成“标准化生产系统”。

V1 最终目标包括：

1. 入口基准固定为全市场统一 `5 / 3 / 3`
2. 普通用户不再调底层候选池参数
3. `Standard` 成为官方生产引擎
4. `Aggressive` 成为进攻补充引擎
5. 总闸门改成 `市场环境 × 当日机会质量 × 历史有效性`
6. 行动清单和盘中信号受总闸门约束
7. 页面与规则口径保持一致

## 4. 实施原则

V1 改造优先遵守 6 条原则：

1. 先统一入口，再重构后面的决策层
2. 先收口 `Standard` 官方链路，再定义 `Aggressive` 的补充位置
3. 先稳定总闸门，再去优化提示文案和 AI 解读
4. 先让 API / Schema 成型，再改页面
5. 每个阶段都允许“先降级可用”，不追求一次到位
6. 回归测试必须跟着阶段推进，而不是最后集中补

## 5. 总体实施顺序

推荐 V1 改造顺序如下：

1. 候选池入口标准化
2. `Standard / Aggressive` 职责重构
3. 总闸门重构
4. 行动清单规则收口
5. 盘中信号权限与语言边界收口
6. API / Schema 冻结
7. 前端页面改造
8. 联调与回归测试

## 6. M0：入口标准化

优先级：`P0`

目标：

- 把候选池入口从“用户可调参数”改成“V1 固定生产基线”

任务：

### 后端

- 固定 V1 候选池入口为：
  - `最小涨幅 = 5%`
  - `最小成交额 = 3亿`
  - `最小换手率 = 3%`
- 固定市场范围为：
  - 主板
  - 创业板
  - 科创板
- 移除或停用普通用户请求里的入口调参分支
- 保留版本字段：
  - `entry_baseline_version`
  - `market_scope_version`

### API

- 逐步收紧公开请求参数
- 明确 `top_n` 只影响展示，不影响二次决策

### 前端

- 隐藏：
  - 最小涨幅
  - 最小成交额
  - 最小换手率
- 页面只保留：
  - 交易日
  - 评分画像
  - 返回数量

### 测试

- 验证固定入口后候选池稳定性
- 验证 `top_n` 不再影响二次决策主组合

## 7. M1：Standard / Aggressive 职责重构

优先级：`P0`

目标：

- 把 `Standard` 固化为官方生产引擎
- 把 `Aggressive` 固化为进攻补充引擎

任务：

### 后端

- `Standard` 输出：
  - 官方今日出手级别
  - 官方默认组合
  - 官方主仓 / 次仓 / 观察仓
- `Aggressive` 输出：
  - 进攻补充视图
  - 弹性观察对象
  - 更强参与性说明
- 为 `Aggressive` 增加 10% 振幅容忍规则
- 确保 `Aggressive` 不能推翻总闸门

### API

- 明确返回结构中：
  - 哪部分是 official
  - 哪部分是 aggressive supplement

### 前端

- 页面展示上避免给用户“两个官方答案”的错觉
- 把 `Aggressive` 语义统一成“进攻补充”

### 测试

- 验证 `Standard` 与 `Aggressive` 的角色边界
- 验证 `Aggressive` 不会单独翻盘“今日不做”

## 8. M2：总闸门重构

优先级：`P0`

目标：

- 把当前“20/60 历史验证单独裁决”改成“三层联合裁决”

任务：

### 后端

- 新增市场环境层计算
  - 指数趋势
  - 赚钱效应
  - 情绪强弱
  - 主线扩散
- 新增当日机会质量层计算
  - 主线清晰度
  - 默认组合质量
  - 买点清晰度
  - 角色结构完整度
  - 风险可控度
- 保留历史有效性层
  - 20日当前可用性
  - 60日结构可信度
- 改成：
  - 市场环境 × 当日机会质量 = 基础级别
  - 历史有效性 = 上限控制
- 增加强烈可做升级条件

### API

- 返回 3 层结果：
  - `market_environment`
  - `opportunity_quality`
  - `historical_validity`
- 返回最终：
  - `action_level`
  - `recommendation_cap`

### 前端

- 重新组织“今日出手级别”说明区
- 让用户能看到为什么是：
  - 强
  - 中
  - 弱

### 测试

- 强市 + 历史偏弱时，应能落到 `谨慎出手`，而不是直接 `今日不做`
- 市场弱 + 机会弱时，必须仍然能正确劝退

## 9. M3：行动清单规则收口

优先级：`P1`

目标：

- 让五档出手级别真正控制行动清单权限

任务：

### 后端

- 完整版行动清单：
  - 仅用于 `强烈可做 / 可正常出手`
- 简化版行动清单：
  - 仅用于 `谨慎出手`
- `仅观察 / 今日不做`
  - 不生成行动清单

### API

- 增加：
  - `checklist_mode`
  - `action_checklist`

### 前端

- 按级别展示：
  - 完整版
  - 简化版
  - 不展示

### 测试

- 验证不同行动级别对应的清单权限
- 验证 `谨慎出手` 不会出现多票并行执行话术

## 10. M4：盘中信号纪律收口

优先级：`P1`

目标：

- 让盘中信号页只做“昨晚规则的盘中播报器”

任务：

### 后端

- 固化盘中 4 条纪律：
  - 不改昨晚顺序
  - 不推翻总闸门
  - 不对偏离过大的票给追入暗示
  - 不临时新增股票
- 固化允许的单票状态：
  - 买点已触发
  - 接近触发
  - 尚未触发
  - 触发失败
  - 偏离过大
  - 保留观察
- 固化整页最终输出：
  - 建议买
  - 仅主仓可考虑
  - 保留观察但不建议执行
  - 不建议买
- 增加语言黑名单约束

### API

- 明确盘中接口只返回允许状态
- 明确盘中接口不会提升前一晚总闸门

### 前端

- 盘中页文案和状态标签统一
- 禁止在 `仅观察 / 今日不做` 下出现买入暗示型 UI

### 测试

- 验证“仅观察”不会在盘中翻盘成“建议买”
- 验证“今日不做”不会在盘中被 Aggressive 抬高

## 11. M5：API / Schema 冻结

优先级：`P1`

目标：

- 把 V1 规则稳定映射成后端接口契约

任务：

### 接口

- 冻结：
  - 筛选结果接口
  - 二次决策接口
  - 盘中信号接口
- 冻结关键枚举：
  - `action_level`
  - `recommendation_cap`
  - `checklist_mode`
  - `portfolio_slot`
  - `buy_point_status`
  - `intraday_status`

### 数据兼容

- 尽量追加字段，不破坏已有客户端
- 对旧字段保留兼容层或过渡说明

### 测试

- schema 回归测试
- 前后端联调测试

## 12. M6：前端页面改造

优先级：`P1`

目标：

- 让页面和 V1 产品规则一致

任务：

### 强势筛选主页面

- 收掉普通用户调参面板
- 强化：
  - 交易日
  - 画像
  - 返回数量

### 二次决策区

- 重构今日出手级别区
- 展示三层总闸门结论
- 强化官方组合与观察边界

### 盘中信号区

- 展示权限约束
- 展示最终 60 分钟收口

### 文案

- 清楚区分：
  - 官方生产结论
  - 进攻补充视图

## 13. M7：联调与回归测试

优先级：`P1`

目标：

- 确认规则、接口、页面、交互四层口径一致

任务：

### 后端

- 核心规则单元测试
- API 集成测试

### 前端

- 页面渲染测试
- 关键路径交互测试

### 联调

- `Standard` 官方链路
- `Aggressive` 补充链路
- 总闸门各档位
- 行动清单权限
- 盘中纪律

## 14. 优先级总表

### `P0`

- 入口标准化
- `Standard / Aggressive` 职责重构
- 总闸门重构

### `P1`

- 行动清单规则
- 盘中纪律
- API / Schema 冻结
- 前端页面改造
- 联调回归

### `P2`

- 更复杂的历史验证表现页
- 更细的解释层与 AI 联动优化
- V1.5 以后再考虑的实验型能力

## 15. 一句话版结论

如果只记这份清单的一句话，可以直接记：

**V1 改造要先把入口、画像职责和总闸门这三件底层规则定成生产基线，再去改行动清单、盘中信号、页面和接口。**
